Draft notes for 0.6.0 (the part that connects POSIX programs to the data volume; the rest of the release adds its own sections before the tag).

## Highlights

- **POSIX programs see `/data`.** The data file service (`datafs`, littlefs on the data disk) serves `/data` to every POSIX program: files, directories, modes, owners, permissions by the identity of the process, `fsync`, `rename`, `ftruncate`, `utimensat`, `O_APPEND`, and a directory as the current directory. Names are durable when the call returns, file data at `fsync` or at the close, and a file written to a temporary name and renamed over the old one leaves one whole generation after a power cut. `docs/data.md` says what a program gets.
- **Identity and permissions.** The service asks the process service who the caller is and applies the rules of POSIX (the same code as the RAM file service). A description keeps the rights it was opened with over `chmod`, `setuid`, `fork`, `exec` and a pass through a socket.
- **Probes.** `data-posix` (the read, write, restart and crash probes of the layer), `open-posix --data` (the file-related Open POSIX tests with their scratch files on the volume: 92 of 111 pass, the 19 that map a file shared are ENODEV by design) and `data-save` (a file saved the way `sed -i` saves it, read back after a reboot).

## Limits

- `/data` holds up to 1,024 directories and about 20,000 to 30,000 files with names up to 32 bytes (about 6,000 with names of 255 bytes), up to 1,024 entries in a directory; every file takes at least 4 KiB. Beyond that creation answers ENOSPC; removal always works. One removal takes up to about 2 s on EBS gp3, a tree of a thousand directories about 18 minutes.
- A call moves 1 KiB at most (1,012 bytes of a write, 1,004 of a pwrite), so a large file is thousands of calls (8 MiB took 8,290 write calls and 11.4 s under QEMU). A write of more than one message can have another process's bytes between its messages: two processes appending records of more than 1 KiB to one file can interleave them, and a reader of a file rewritten in place can see old and new bytes in one read. The fix (a transfer through a memory object) is planned after 0.6.
- A shared mapping (`MAP_SHARED`) of a file of `/data` is ENODEV; a private mapping works. Record locks are ENOLCK, a program is never run from `/data` (EACCES), the volume has no links (`link` of a file is EMLINK, `symlink` EPERM, `rename` across file systems EXDEV), and `a/ghost/..` under `/data` is read as text and names `a`.
- A volume of 0.5.1 is converted after the service says READY: an entry that has not had its turn shows root, group 0 and mode 0600 (0700 for a directory).
- An image with no data service answers EIO after a second for a path under `/data`.

- Reads never update `atime`: the volume behaves as if mounted `noatime`.
- The first call under `/data` after a boot can wait for the first walk of the volume (up to about a minute on a full 2 GiB volume on EBS gp3).
- A process holds at most 32 open descriptions of `/data` (the 33rd `open` is EMFILE while descriptor numbers are free; a duplicate of a descriptor shares its description and costs none). A process tree has 8 requests in flight at once, and everyone logged in through `sshd` shares one tree.
- `unlink` of a directory answers EISDIR (use `rmdir`).
- Measured under QEMU: about 2 MiB a second written and 1.3 MiB a second read (64 MiB in 31 s and 48 s), one message of 1 KiB a call. Removing a tree of a thousand directories takes about 18 minutes on EBS gp3 (3.3 million reads at 3,000 reads a second).
- Going back: the service of 0.5.2, if it is released, refuses a volume that 0.6 has marked with format 4. The service of 0.5.1 mounts such a volume and ignores its permissions. A volume converted by 0.6 is not converted back.

## Compatibility

The series 0.6 is open until the release. Against 0.5 the fingerprint in `packages/abi.txt` moved in two parts and held in two: `libc` (the names `libc.so` exports) and `layouts` (the layouts and constants of the headers) are the same, so a program built for 0.5 links against 0.6; `loader` and `protocols` changed.

- **Loader.** The start area has a slot `Data` (14, the session with the data file service) and a descriptor name `Names::Data` for a description of the volume; the loader's version is 7 and the start area's 10. A set-ID program gets the session of its parent only when the data service's root vouches for it, else its slot is empty.
- **`proto_process` version 16.** TakeRoot (method 44) gives a process the root of the data service, with SEND and TRANSFER; the root `ROOT_DATA` (4) and the notary mark `DATAFS` join the roots that a service registers.
- **`proto_pipe` version 4.** SOCK_SEND, SOCK_SEND_TAKE and the reply of SOCK_RECV carry a word of kinds after the count of descriptions (4 bits each: none, the network service, the data service), so a description of `/data` travels in SCM_RIGHTS.
- **`proto_data` version 3.** The layer speaks the protocol of the data service, which enters the closure of the layer: the stat record of 64 bytes, BIND, SESSION, VERIFY_SESSION, WHERE, ACCESS and the calls that change modes, owners and times.
