The second release of stafeto closes subproject 2 (POSIX, services and file systems). It is a POSIX system on its own capability microkernel, written in Rust for AArch64. It boots in QEMU (`virt`) on any host, with HVF acceleration on a Mac with Apple silicon, on 1 to 4 CPUs.

## Try it

Download `stafeto-0.2.0-aarch64-virt.tar.xz`, unpack it and run `./run.sh` (`--cpus 4` for four CPUs, `--hvf` on a Mac with Apple silicon). You get a BusyBox `ash` shell; `bash`, `nano`, `htop`, `top` and `ncdu` are in the image. `exit` or Ctrl-A X ends QEMU; `run.sh` tells how to install `qemu-system-aarch64` if it is missing.

## Highlights

- **Kernel.** A small capability microkernel (193,216 bytes of a 204,800-byte budget): synchronous IPC with priority inheritance, memory objects and mappings, interrupts as notifications, partitioned fixed-priority scheduling. The longest stretch without an interrupt is 8,870 instructions (limit 18,000); on 4 CPUs it is 20,870 (limit 32,000), with the one object lock held for at most 3,914 of 4,000 instructions.
- **POSIX.** 1,035 of 1,035 required interfaces present, none of them answers only `ENOSYS`. os-test `basic` passes 1,184 of 1,187 tests (the three outside are the `dlfcn` tests); the Open POSIX Test Suite passes 1,986 of 2,036 tests (a full run also shows 1 FAIL, 1 TIMEOUT, 14 UNRESOLVED, 28 UNSUPPORTED and 6 UNTESTED; the map is in `docs/open-posix-map.md`). Files, pipes, local sockets, signals and real-time signal queues, timers, threads, `mmap`, file locks, `/proc`.
- **Utilities.** 103 of the 112 POSIX utilities: BusyBox 1.37, the ready-made programs `getconf`, `join`, `pathchk`, `file`, `iconv`, `compress`, `csplit`, `gencat`, `m4`, `write`, `pr`, `pax`, `newgrp`, `tput`, `tabs`, and the built-ins of `ash`. GNU bash 5.3, GNU nano, htop and ncdu run on relibc.
- **Shared C library.** `libc.so` with a dynamic loader: BusyBox, bash, nano, htop and ncdu are linked dynamically and share the code pages of the library between processes. The shell image shrank from 9.6 to 7.0 MB.
- **Graphics and input preview.** Services for virtio-gpu (2D) and virtio-input give one program the screen and the keyboard at a time; `libc.so` exports `stafeto_display_*` and `stafeto_input_read`. Doomgeneric with the Freedoom data runs in QEMU: `cargo xtask doom --machine hvf` opens a window, and `doom -iwad /games/freedoom1.wad` from `ash` plays the first level (`docs/doom.md`). The full graphics subproject comes later.
- **Memory and threads.** `PROT_EXEC` for private mappings (write and execute together give `ENOTSUP`), `SIGBUS` past the end of a mapped file, and mutexes, condition variables and semaphores shared between processes, woken by the pipe service in priority order.
- **Several CPUs.** Up to 4 CPUs with per-CPU data, one short object lock, commands between CPUs and QSBR; scheduling stays partitioned, so a real-time CPU keeps its bounds (`docs/smp.md`).
- **Real-time tools.** Measured bounds are checked in CI, and `cargo xtask wcet` reports block coverage, kernel stack depth and a static bound per call (`docs/wcet.md`).
- **Release files.** The kernel with symbols, the sources of every GPL package with our build scripts and patches, an SPDX SBOM and `SHA256SUMS`.

## Limits

- QEMU `virt` only; the PinePhone and other boards come later.
- The file system lives in RAM: changes are gone after a restart.
- No network or sound yet; graphics is a preview with one full-screen program.
- Nine POSIX utilities wait for services of their own: `at`, `batch`, `lp`, `mailx`, `locale`, `localedef`, `gettext`, `ngettext` and `msgfmt`.
- `dlopen` of a new library is not there yet.
- Interfaces may still change inside 0.x.

## Known departures

Two tests of a full Open POSIX run do not pass. `stress/threads/fork/s-c1` gives the verdict "not scalable", which depends on the size of the fork pool (#508). `mmap/10-1` ends with TIMEOUT after 86 s (#501). The fixes are planned for 0.2.1. `mmap/5-1`, `mmap/11-2` and `mmap/11-3` are fixed in 0.2.0: `mmap` and `mprotect` accept `PROT_EXEC`, and a read past the end of a mapped file raises SIGBUS (#384).
