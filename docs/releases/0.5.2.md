The release 0.5.2 of stafeto is a patch release of the series 0.5. It is 0.5.1 with nginx and nginx-fast updated to 1.30.7, which fixes nine security issues, and nothing else changes. The kernel is still a small capability microkernel in Rust for AArch64; it boots in QEMU (`virt`) on any host, with HVF acceleration on a Mac with Apple silicon, under Apple Virtualization.framework, and on AWS EC2 Graviton.

## Try it

Download `stafeto-0.5.2-aarch64-virt-base.tar.xz` (the shell, the package tool and the base packages) or `stafeto-0.5.2-aarch64-virt-full.tar.xz` (every package, including the network programs; it needs 1024M of memory), unpack it and run `./run.sh` (`--cpus 4` for four CPUs, `--hvf` on a Mac with Apple silicon).

## Try it on AWS

The public AWS image of 0.5.2 replaces the image of 0.5.1. It has the same contents, launch steps and limits as described in the notes of 0.5.1 (`docs/releases/0.5.1.md`), with nginx and nginx-fast 1.30.7. AMI: `ami-09b3283d1b189c12b` in `eu-central-1` (public, name `stafeto-0.5.2`, arm64, UEFI). It was checked on a t4g.small: `uname -r` 0.5.2, the clock from the firmware, the data volume, nginx 1.30.7 on 80 and 443, nginx-fast on 8080, SSH with the key pair of the instance, and `pkg update` at the index of serial 3. The image of 0.5.1 is no longer public.

## What changed

The packages `nginx` and `nginx-fast` are nginx 1.30.7. The nine issues that this version fixes, from the nginx security advisories:

- CVE-2026-123634: use-after-free during response processing in the resolver.
- CVE-2026-123007: memory corruption in HTTP/2 flow control.
- CVE-2026-121810: use-after-free in HTTP/3.
- CVE-2026-123633: use-after-free in HTTP/2.
- CVE-2026-118899: infinite loop while reading a client request body over TLS 1.3.
- CVE-2026-113425: use-after-free in the mail proxy module.
- CVE-2026-125283: buffer overflow when using `alias` with `try_files`.
- CVE-2026-120967: SNI bypass when using client certificate validation in `stream`.
- CVE-2026-123640: insufficient validation in the `stream` module `ssl_preread`.

## Updating

A system of the series 0.5 gets the new packages with `pkg update && pkg upgrade`. Packages built into an image are not updated that way: the full image carries nginx, so a system that runs the full image needs the 0.5.2 image.

## Compatibility

The ABI of the series 0.5 stays frozen and does not change: `cargo xtask abi --check` reports `series 0.5 frozen, no change`, and the packages of 0.5.0 and 0.5.1 run on 0.5.2. The limits of 0.5.1 apply to this release.

The data service of this release (`datafs`) has no check of a volume format number and reads no format mark. It mounts a data partition that carries the attribute `FORMATTED` as a littlefs file system; when the mount fails it prints `datafs: the data volume does not mount, left alone` and writes nothing. A volume formatted by the 0.6 series (format 4) is not covered by this release: the service neither recognizes nor refuses it, so do not attach such a volume to a system of 0.5.2.

## Third-party notices and sources

The notices of the system and of the packages of each image are in `LICENSES/` of the archives, as in 0.5.1. The only changed third-party component is nginx 1.30.7 (BSD-2-Clause). The archive `stafeto-0.5.2-gpl-sources.tar.xz` holds the sources of the GPL packages of both images, the stafeto tree at the release commit and relibc at its pin. The tree is public at `https://github.com/stafeto/stafeto`.
