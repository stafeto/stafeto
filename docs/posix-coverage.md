# POSIX interface inventory

`cargo xtask coverage` compares exported names in relibc's `libc.a` and stafeto's `libposix_crt.a` with [POSIX.1-2024 System Interfaces](https://pubs.opengroup.org/onlinepubs/9799919799/functions/contents.html). It also preprocesses available headers for macro names and checks the [Base Definitions header inventory](https://pubs.opengroup.org/onlinepubs/9799919799/basedefs/contents.html). The command writes `target/measure/posix-coverage.tsv` and `target/measure/posix-headers.tsv`, and builds both archives when run without arguments. For an existing build, use `cargo xtask coverage --libc path/to/libc.a --crt path/to/libposix_crt.a`; relibc's sources are read from `source/` beside `sysroot/` of that `libc.a`.

A function that exists but answers ENOSYS on stafeto is a stub (availability `stub-enosys`) and does not count as covered. The stubs come from relibc's sources (`xtask/src/stubs.rs`): a platform method whose whole body is `Err(Errno(ENOSYS))`, a trait default that only calls stubs, and a public function that only hands its arguments to stubs. A public function is a stub when every call it makes is a stub (through `Sys::` or a function of relibc), with opening and closing a descriptor not counting, so `statvfs` (over its stubs) is found. A short list of stubs the reading misses (`mkdtemp`, `realpath`) is kept by hand in `xtask/src/stubs.rs`. A function that answers ENOSYS for some arguments only, or does more work around a stub, is not found. The summary prints the coverage as exported symbols plus header macros over the interfaces of each requirement level.

The checked-in [XSH inventory](../tests/posix/2024-xsh.tsv) records names, reference pages, headers, and option codes. The [XBD inventory](../tests/posix/2024-xbd-headers.tsv) records all 86 standard headers and their option status. Regenerate both with `python3 tools/posix-inventory.py --cache /tmp/posix-2024 --output tests/posix/2024-xsh.tsv --xbd-output tests/posix/2024-xbd-headers.tsv`. The extractor reads the official pages and keeps downloaded HTML in the requested cache directory. Its current extraction covers 701 distinct XSH reference pages, 1,241 names, and 1,035 names outside optional regions; XBD has 70 required headers. The inventory includes named objects such as `errno` and the `CMPLX` macros. Alternate XSH URLs can serve identical page content. The cached pages are omitted from the repository.

The extractor reconciles NAME and indexed SYNOPSIS declarations with the [alphabetical index](https://pubs.opengroup.org/onlinepubs/9799919799/idx/functions.html). This includes the `FD_*` macros and `_Fork`, and discovers the `va_arg` page omitted by the contents index. `getdate_err` is an XSI object: its declaration scope comes from XBD `time.h`, since XSH DESCRIPTION defines it without an option marker. The index retains historical links for `asctime_r` and `ctime_r`; Issue 8 Defect 1410 removes those functions, so they are explicitly excluded. Unexpected or unresolved index differences stop generation. Focused extraction tests run with `python3 tools/test_posix_inventory.py`; inventory and symbol/macro parsing tests run with `cargo test -p xtask coverage`.

An `exported-symbol` row has a linker-visible entry point. A `header-macro` row names a macro seen when compiling the listed header for AArch64. An `unresolved` row needs review for missing headers, preprocessing failures, inline functions, or implementation work. The command prints the header scan counts. Guest tests establish behavior, error handling, and service availability. The complete conformance gate will combine this inventory with os-test and Open POSIX results.

This tooling does not complete stage 5j / issue #145. The `unistd.h` macros and `sysconf` agree with each other; the complete os-test/Open POSIX gate, the full conformance of the options (stage 5k), and synchronous faults delivered as signals remain separate work after the file-service stage.

## Departures from POSIX.1-2024

- **Utilities (Ф10).** 94 of the 112 utilities of XCU answer `command -v` in the shell image: the ten builtins of `ash`, `sh`, 77 applets of BusyBox 1.37 (a second build of BusyBox, `target/busybox-utils`, only for the image of the shell; the probes keep the small one) and six ready-made programs BusyBox lacks, built from their own sources unchanged (`tools/build-ready-utils.py`) and named as BusyBox applets: `getconf`, `join`, `pathchk` (sbase, MIT), `file`, `iconv` (toybox 0.8.15, 0BSD) and `compress` (ncompress 5.0, public domain; its code tables are 14 bits, 180 kB of static memory, so `compress` writes files of at most 14-bit codes). Not provided, because no ready-made program is built for them yet: `at batch csplit gencat gettext locale localedef lp m4 mailx msgfmt newgrp ngettext pax pr tabs tput write`. `ps` is BusyBox's: `/proc` is made by the layer when a path is opened (`/proc/<pid>/stat`, `cmdline`, `status`, `/proc/uptime`; the listing of `/proc` names the live PIDs) from the List request of the process service; it is read only (EROFS), shows no threads, memory sizes, times or tty names beyond the terminal's device number, and the name of a process is the last component of the path of its program (a process of the init table has none, `ps` shows `?`). `getlogin` takes the line of the terminal from `/var/run/utmpx` (the image carries one record) and otherwise the owner of the real user ID; `syslog` appends to `/var/log/messages` and writes to the standard error where the file cannot be opened; `utmpx` has no writer in the system (`pututxline` works on a file the process owns, `utmpxname`). `getrusage`, `nice`, `getpriority` and `setpriority` are still not provided.
- **Sockets (Ф9).** AF_UNIX and the IPv4 loopback only; the sockets are descriptions of the pipe service (40 in all, 20 for a session, 28 for a tree of processes, a buffer of 4 KiB each, SO_RCVBUF and SO_SNDBUF report it). A message carries at most 800 bytes, so a datagram larger than that is EMSGSIZE and a stream send is cut into pieces of 800; an IPv4 datagram to a port nobody has is lost, as on a network, and one that finds the buffer of its receiver full is dropped. `connect` to a listener completes at once (the queue holds 4 connections; a full queue is ECONNREFUSED), so there is no EINPROGRESS. Only 127.0.0.0/8 and 0.0.0.0 are addresses (ENETUNREACH, EADDRNOTAVAIL for others); a name in the file system is a node of kind socket made by `bind`, and `connect` finds the socket by the node number, so a name made anew takes the binding from the stale socket. SCM_RIGHTS carries descriptions of the pipe service (pipe ends and sockets), 8 in a message and 4 messages in flight to a socket; a regular file, a terminal and a FIFO are EOPNOTSUPP. Out-of-band data is the last byte of a stream send with MSG_OOB, apart from the stream. Not provided: SOCK_SEQPACKET, AF_INET6, SCM_CREDENTIALS, SO_LINGER, SO_RCVTIMEO, SO_SNDTIMEO, a blocking `connect` to a full queue. A close of a descriptor by one thread does not wake another thread that waits on it. A socket cannot be sent in a message to itself, while it holds a message with descriptions, or to a socket that is itself in flight (ETOOMANYREFS), so that no cycle keeps a slot.
- **Message queues, semaphores and shared memory (Ф11b).** The POSIX message queues (`mq_*`), the named semaphores (`sem_open`) and the XSI queues, semaphore sets and segments (`msg*`, `sem*`, `shm*`) live in the pipe service (`services/pipe/src/ipc.rs`, protocol `proto/pipe/src/ipc.rs`, three methods). Limits: 16 queues of both kinds, 64 messages of at most 512 bytes in all, 16 messages in a queue (`mq_maxmsg`), 8 semaphore sets of 16 semaphores (named semaphores are sets of one), 8 segments of at most 1 MiB, 6 objects of a kind and 32 of the 64 messages for a tree of processes (a sender that finds the pool used up waits for any message to go); the default `mq_msgsize` is 512, `mq_maxmsg` 8, XSI `msg_qbytes` 8192 (at most 16384). A queue descriptor takes one of the 40 description slots of the sockets, so it counts in the 20 of a session and 28 of a tree; `read`, `write` and `poll` on it fail (poll reports POLLNVAL), and a queue taken out of its name lives until its last descriptor closes. `mq_notify` runs a helper thread of the process that waits in the service; a child of `fork` has no registration. The service learns who a caller is from the process service: a session brings a copy of its process's identity session (`posix-id`) with its first request (and again where the service answers that it has none, as in a child of `fork`), the service has it vouched (Vouch, through a notary session as for the clock and the file service; `pipe` is in the VOUCHERS of init) and remembers the answer with the generation of the credentials; only the time comes in the request. The name of a queue or of a named semaphore is taken away by its owner (EACCES otherwise). `SEM_UNDO` keeps 32 adjustments, `shmat` and `sem_open` 48 holds for the service; a process that goes, or replaces its image by `exec`, gives them back in steps, and a child of `fork` gets copies of the holds of its parent (it is counted in `shm_nattch`; `fork` fails with EAGAIN where the holds have no room). The pages of a segment are the file `/dev/shm/.sysvN`, owned by the creator with the mode of the segment (`IPC_SET` follows with `chmod`, `chown` where the caller may), so that the file service refuses those the segment refuses; it is removed with the segment, and where the segment is freed in the service after a process was killed, the next answer to its creator names the file (16 are kept). The name of the file is the creator's 64-bit random number (`getrandom`), made with `O_EXCL` and mode 0600 before it gets the segment's mode, and `shmat` takes the file only if it is a regular file of one link, as long as the segment and owned by the segment's owner or creator (EACCES otherwise), so that a file put in its place in `/dev/shm` is refused. `IPC_SET` changes the file first and the segment after: a new owner or group (which only the superuser may give a file) from anyone else, or a mode its owner may not give, is EPERM and nothing changes. `shmat` takes no address. `semtimedop`, `msgctl` info commands and `IPC_INFO` are not provided. The worst step of the service for these calls is 14,569 ticks of B = 20,410 (with 48 waiting operations) (`cargo xtask posix-ipc-steps`).
- **Message catalogs, crypt, getdate, dlopen (Ф11b).** `catopen`, `catgets` and `catclose` read the catalog format of the BSDs, which `gencat` (FreeBSD's, in the images of os-test only) writes; NLSPATH and the default `/usr/share/nls/%L/%N.cat` are searched. `crypt` knows the traditional DES (musl's code of FreeSec), `setkey` and `encrypt` the same cipher. `getdate` follows DATEMSK. `dlopen(NULL)` answers a handle of the program, `dlsym` finds no symbol by name in a statically linked program, and every other `dlopen` fails with a message that says so.
- **Real-time signals.** Issue 8 puts the real-time signals in the base. The layer has the signals 1 to 31 and refuses SIGRTMIN to SIGRTMAX (EINVAL), and the process service keeps one place for each signal: `sigqueue` answers EAGAIN while the signal waits, so at most 31 signals are queued ({SIGQUEUE_MAX} should be 32 at least) and two timers that send the same number share one place (the second counts as an overrun). `_POSIX_REALTIME_SIGNALS` is not defined and `sysconf(_SC_REALTIME_SIGNALS)` is -1; `sysconf(_SC_SIGQUEUE_MAX)` gives the 31 there are.
- **Absolute times.** A CLOCK_REALTIME timer set with TIMER_ABSTIME turns its time into the monotonic scale when it is armed; a later `clock_settime` does not move it.
- **Processor time.** There is none: `clock()` gives the time since the process began, ITIMER_VIRTUAL and ITIMER_PROF are EINVAL.
