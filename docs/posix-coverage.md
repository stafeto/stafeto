# POSIX interface inventory

`cargo xtask coverage` compares exported names in relibc's `libc.a` and stafeto's `libposix_crt.a` with [POSIX.1-2024 System Interfaces](https://pubs.opengroup.org/onlinepubs/9799919799/functions/contents.html). It also preprocesses available headers for macro names and checks the [Base Definitions header inventory](https://pubs.opengroup.org/onlinepubs/9799919799/basedefs/contents.html). The command writes `target/measure/posix-coverage.tsv` and `target/measure/posix-headers.tsv`, and builds both archives when run without arguments. For an existing build, use `cargo xtask coverage --libc path/to/libc.a --crt path/to/libposix_crt.a`; relibc's sources are read from `source/` beside `sysroot/` of that `libc.a`.

A function that exists but answers ENOSYS on stafeto is a stub (availability `stub-enosys`) and does not count as covered. The stubs come from relibc's sources (`xtask/src/stubs.rs`): a platform method whose whole body is `Err(Errno(ENOSYS))`, a trait default that only calls stubs, and a public function that only hands its arguments to stubs. A public function is a stub when every call it makes is a stub (through `Sys::` or a function of relibc), with opening and closing a descriptor not counting, so `statvfs` (over its stubs) is found. A short list of stubs the reading misses (`mkdtemp`, `realpath`) is kept by hand in `xtask/src/stubs.rs`. A function that answers ENOSYS for some arguments only, or does more work around a stub, is not found. The summary prints the coverage as exported symbols plus header macros over the interfaces of each requirement level.

The checked-in [XSH inventory](../tests/posix/2024-xsh.tsv) records names, reference pages, headers, and option codes. The [XBD inventory](../tests/posix/2024-xbd-headers.tsv) records all 86 standard headers and their option status. Regenerate both with `python3 tools/posix-inventory.py --cache /tmp/posix-2024 --output tests/posix/2024-xsh.tsv --xbd-output tests/posix/2024-xbd-headers.tsv`. The extractor reads the official pages and keeps downloaded HTML in the requested cache directory. Its current extraction covers 701 distinct XSH reference pages, 1,241 names, and 1,035 names outside optional regions; XBD has 70 required headers. The inventory includes named objects such as `errno` and the `CMPLX` macros. Alternate XSH URLs can serve identical page content. The cached pages are omitted from the repository.

The extractor reconciles NAME and indexed SYNOPSIS declarations with the [alphabetical index](https://pubs.opengroup.org/onlinepubs/9799919799/idx/functions.html). This includes the `FD_*` macros and `_Fork`, and discovers the `va_arg` page omitted by the contents index. `getdate_err` is an XSI object: its declaration scope comes from XBD `time.h`, since XSH DESCRIPTION defines it without an option marker. The index retains historical links for `asctime_r` and `ctime_r`; Issue 8 Defect 1410 removes those functions, so they are explicitly excluded. Unexpected or unresolved index differences stop generation. Focused extraction tests run with `python3 tools/test_posix_inventory.py`; inventory and symbol/macro parsing tests run with `cargo test -p xtask coverage`.

An `exported-symbol` row has a linker-visible entry point. A `header-macro` row names a macro seen when compiling the listed header for AArch64. An `unresolved` row needs review for missing headers, preprocessing failures, inline functions, or implementation work. The command prints the header scan counts. Guest tests establish behavior, error handling, and service availability. The complete conformance gate will combine this inventory with os-test and Open POSIX results.

The `unistd.h` macros and `sysconf` agree with each other. `cargo xtask ci` (group `host`) runs `cargo xtask coverage` and `cargo xtask os-test-headers` on the host: a name of `tests/posix/coverage-pass.txt` (an interface with a symbol or a macro, a header present) or of `tests/os-test/headers-pass.txt` (a test of the `include` and `namespace` suites of os-test that compiles and links against the sysroot) that stops passing fails the step, and `STAFETO_BLESS=1` rewrites a list from a run. The measure of 2026-11-01 (relibc 1cd3d139): 1,035 of 1,035 required and 206 of 206 optional interfaces have a symbol or a macro, 70 required and 16 option headers are present, 3,488 of 3,758 `include` tests are good (64 missing headers, 45 missing optional headers, 140 undeclared names, 10 incompatible types, 6 undefined symbols, 3 unknown types, 2 compile errors) and 23 of 159 `namespace` tests are good (132 show pollution of the namespace, 4 miss the header). The Open POSIX gate, the full `basic` suite of os-test, the synchronous faults as signals and the guest tests of the options are in `cargo xtask ci` as well.

## Departures from POSIX.1-2024

- **Utilities.** 103 of the 112 utilities of XCU answer `command -v` in the shell image: the ten builtins of `ash`, `sh`, 77 applets of BusyBox 1.37 (a second build of BusyBox, `target/busybox-utils`, only for the image of the shell; the probes keep the small one) and 15 ready-made programs BusyBox lacks, built from their own sources unchanged (`tools/build-ready-utils.py`) and named as BusyBox applets: `getconf`, `join`, `pathchk` (sbase, MIT), `file`, `iconv` (toybox 0.8.15, 0BSD), `compress` (ncompress 5.0, public domain; its code tables are 14 bits, 180 kB of static memory, so `compress` writes files of at most 14-bit codes), `csplit`, `gencat`, `m4`, `write` (chimerautils 15.1.2, BSD), `pr` (nbase 10.1.0.29, BSD-3-Clause), `pax` (paxmirabilis 20240817, BSD and MirOS, with the fts of musl-fts 1.2.7), `newgrp` (util-linux 2.42.4, GPL-2.0-or-later) and `tput`, `tabs` (ncurses 6.6, MIT). Not provided, because they wait for services (scheduling, printing, mail, locales): `at batch gettext locale localedef lp mailx msgfmt ngettext`. `ps` is BusyBox's: `/proc` is made by the layer when a path is opened (`/proc/<pid>/stat`, `statm`, `cmdline`, `status`, `/proc/uptime`, `stat`, `meminfo`, `loadavg`, and `/proc/mounts` in Linux's format for `df`; a path reaches `/proc` by its absolute form, so `./proc/1` from `/` is the same node; the listing of `/proc` names the live PIDs in ascending order, the offset after a PID being the PID plus 4, so a listing in several calls takes each process that lives throughout once; `statvfs` of `/proc` has no blocks) from the List request of the process service; the path is read as text: `/missing/../proc/1` and `/etc/passwd/../proc` succeed (Linux answers ENOENT and ENOTDIR), the search rights of the directories on the way are not checked, and `/link/../proc` is taken by its text; it is read only (EROFS), shows no threads or tty names beyond the terminal's device number, and counts all the time of a process as user time (`utime`: the layer has the split, `/proc` does not read it yet); the memory of a process (`VmSize`, `VmRSS`, `statm`, `vsize` and `rss` of `stat`) is the memory charged to its quota, all of it resident; `/proc/meminfo` gives `MemTotal` as the quota of the process service (the memory the POSIX processes share) and `MemFree` and `MemAvailable` as what no process holds of it, with zero for buffers, cache, shared memory and swap; `/proc/stat` has the line `cpu` and `cpu0` (the time all processes ran as user time, those that ended included, which the process service keeps in an account of its own, and the rest of the time since the start as idle time; both only grow), `btime` from the clock, `processes` as the highest PID, and zeros for `intr` and `ctxt`; `/proc/loadavg` gives `0.00 0.00 0.00`, since the layer does not see the scheduler's run queue and keeps no averages, with the number of live processes and the highest PID as the last two fields; `/proc/uptime` has the idle time as the time since the start less the time all processes ran; and the name of a process is the last component of the path of its program (a process of the init table has none, `ps` shows `?`). BusyBox `top` (`top -b -n 1` among them) and `resize` are in the shell image as well. `getlogin` takes the line of the terminal from `/var/run/utmpx` (the image carries one record) and otherwise the owner of the real user ID; `syslog` appends to `/var/log/messages` and writes to the standard error where the file cannot be opened; `utmpx` has no writer in the system (`pututxline` works on a file the process owns, `utmpxname`). `getrusage`, `nice`, `getpriority` and `setpriority` are still not provided.
- **Sockets.** AF_UNIX and the IPv4 loopback only; the sockets are descriptions of the pipe service (40 in all, 20 for a session, 28 for a tree of processes, a buffer of 4 KiB each, SO_RCVBUF and SO_SNDBUF report it; the buffer of an AF_UNIX datagram socket holds two datagrams of 800 bytes and reports 1,864 for SO_RCVBUF and 1,600 for SO_SNDBUF). A message carries at most 800 bytes, so a datagram larger than that is EMSGSIZE and a stream send is cut into pieces of 800; an IPv4 datagram to a port nobody has is lost, as on a network, and one that finds the buffer of its receiver full is dropped. `connect` to a listener completes at once while the queue (up to 4 connections) has room, so there is no EINPROGRESS; to a listener with a full queue a socket with O_NONBLOCK is told EAGAIN and a blocking one waits until the listener accepts (a long operation at the listener's list of eight waiting operations; where that list is full the library asks again every 2 ms until a place is free, a signal ends the wait with EINTR, a departure from the order of waiting), as AF_UNIX does on Linux; `connect` on a listening socket is EOPNOTSUPP. A datagram socket with a default destination takes datagrams of that peer only (from others they are lost on the loopback of INET and ECONNREFUSED for a file node), and a connected AF_UNIX datagram socket is writable (POLLOUT) while the buffer of its peer has room for the largest datagram. `accept` counts the connection in the tree of the process that accepts (NFILE past 28). Only 127.0.0.0/8 and 0.0.0.0 are addresses (ENETUNREACH, EADDRNOTAVAIL for others); a name in the file system is a node of kind socket made by `bind`, and `connect` finds the socket by the node number, so a name made anew takes the binding from the stale socket. SCM_RIGHTS carries descriptions of the pipe service (pipe ends and sockets) and sockets of the network service (see Servers), 8 in a message and 4 messages in flight to a socket; a regular file, a terminal and a FIFO are EOPNOTSUPP. Out-of-band data is the last byte of a stream send with MSG_OOB, apart from the stream. `if_nameindex` and `if_nametoindex` know one interface, `lo` with index 1 (`if_freenameindex` has nothing to free); `getprotobyname`, `getprotobynumber` and the `getprotoent` family read `/etc/protocols` of the image, which holds `ip`, `icmp`, `tcp`, `udp`, `ipv6` and `ipv6-icmp`, and keep their position in static state, as POSIX allows. Not provided: SOCK_SEQPACKET, AF_INET6, SCM_CREDENTIALS; SO_LINGER, SO_RCVTIMEO, SO_SNDTIMEO and SO_REUSEPORT are options of the sockets of the network service only (see Servers). A close of a descriptor by one thread does not wake another thread that waits on it. A socket cannot be sent in a message to itself, while it holds a message with descriptions, or to a socket that is itself in flight (ETOOMANYREFS), so that no cycle keeps a slot.
- **Names and `wget` (sub-project 6, stage 3).** The network service (`netd`) gives the image with it IPv4 over virtio-net, so the line on sockets above holds for the image without `netd` only. `getaddrinfo` and `gethostbyname` read `/etc/hosts` and then ask the name servers of `/etc/resolv.conf`, which `netd` writes from its lease or from `/etc/netd.conf`. The resolver reads the first three `nameserver` lines (the other lines, `search` and `options` among them, are skipped), asks for A records only, sends no EDNS and has no TCP (a truncated answer is taken as it is). It makes two rounds over the servers and waits five seconds for each, so a silent server costs 10 seconds and three silent servers 30. A reply counts only from a listed server and port 53, with the number of the query, the QR bit and the question repeated. NXDOMAIN and an answer with no records give `EAI_NONAME`; no answer or a failing server gives `EAI_AGAIN`; a reply that does not parse gives `EAI_FAIL`; a name with a label past 63 bytes or past 253 bytes in all gives `EAI_NONAME` at once. A file with no `nameserver` line is `EIO` (`EAI_SYSTEM`). BusyBox `wget` (in the shell image) speaks TLS 1.2 only and checks no certificate and no signature of the key exchange: it prints `note: TLS certificate validation not implemented`. It suits a download whose content is checked another way (a sum of the file). `nslookup` is the big variant of BusyBox with its own query code, and `dnsd` is BusyBox's small name server.
- **Message queues, semaphores and shared memory.** The POSIX message queues (`mq_*`), the named semaphores (`sem_open`) and the XSI queues, semaphore sets and segments (`msg*`, `sem*`, `shm*`) live in the pipe service (`services/pipe/src/ipc.rs`, protocol `proto/pipe/src/ipc.rs`, three methods). Limits: 16 queues of both kinds, 64 messages of at most 512 bytes in all, up to 64 messages in a queue (`mq_maxmsg`, the size of the pool), 8 semaphore sets of 16 semaphores (named semaphores are sets of one), 8 segments of at most 1 MiB, 8 objects of a kind and 32 of the 64 messages for a tree of processes (a sender that finds the pool used up waits for any message to go); the default `mq_msgsize` is 512, `mq_maxmsg` 8, XSI `msg_qbytes` 8192 (at most 16384). A queue descriptor takes one of the 40 description slots of the sockets, so it counts in the 20 of a session and 28 of a tree; `read`, `write` and `poll` on it fail (poll reports POLLNVAL), and a queue taken out of its name lives until its last descriptor closes. `mq_notify` runs a helper thread of the process that waits in the service; a child of `fork` has no registration. `mq_close` takes off the registration made with that descriptor, also while a child of `fork` holds a copy of it. A `mq_send` that fires the registration of its own process waits (a few milliseconds at most) until the helper has given the notice, so that the signal has arrived when the call returns. A registration with SIGEV_SIGNAL and signal number 0 is taken and sends no signal. `{MQ_PRIO_MAX}` is 32768 (`limits.h`, `sysconf(_SC_MQ_PRIO_MAX)`). The service learns who a caller is from the process service: a session brings a copy of its process's identity session (`posix-id`) with its first request (and again where the service answers that it has none, as in a child of `fork`), the service has it vouched (Vouch, through a notary session as for the clock and the file service; `pipe` is in the VOUCHERS of init) and remembers the answer with the generation of the credentials; only the time comes in the request. The waiters of a named semaphore are served by the priority of their threads, the greater first, the older first among equals (the level comes from the layer in the request), and a `sem_post` hands its unit to one of them; the retry every 2 ms of the library, with no order, is left for a wait that finds the 128 places of the service taken (a departure). The name of a queue or of a named semaphore is taken away by its owner (EACCES otherwise). `SEM_UNDO` keeps 32 adjustments, `shmat` and `sem_open` 48 holds for the service; a process that goes, or replaces its image by `exec`, gives them back in steps, and a child of `fork` gets copies of the holds of its parent (it is counted in `shm_nattch`; `fork` fails with EAGAIN where the holds have no room). The pages of a segment are the file `/dev/shm/.sysvN`, owned by the creator with the mode of the segment so that the file service refuses those the segment refuses. The pipe service keeps the rights of the segment and never calls the file service: after an accepted `IPC_SET` and when a segment is freed it queues a job for the file (a new owner, group and mode, one for each file, a later job of a file replacing the earlier; the removal, which none is dropped for: the place of a freed segment is not given to a new one, and `shmget` answers ENOSPC for it, until the file service has taken the job), and the file service takes the jobs with the call BROKER_JOBS on its broker session, one a call, and runs them (a removal in portions of several steps). The library asks the file service to take the jobs at once after `IPC_SET`, `IPC_RMID` and the `shmdt` that frees a segment, so the file is as the segment is when the call returns; every job is told to the file service as well by a notification on a channel it gave the pipe service (the sure way for a segment freed when its last holder went, whom no call of the library follows), and it takes the job in its next turn of maintenance. The file of a dead creator's segment is gone without any later call, whoever the creator was. The name of the file is the creator's 64-bit random number (`getrandom`), made with `O_EXCL` and mode 0600 before it gets the segment's mode, and `shmat` takes the file only if it is a regular file of one link, as long as the segment and owned by the segment's owner or creator (EACCES otherwise), so that a file put in its place in `/dev/shm` is refused. The library of this build still changes the file itself before `IPC_SET` reaches the service, so a new owner or group from a caller that is not the superuser is EPERM there; the service gives the owner or creator of a segment the change of `shm_perm.uid` and `gid` and its job gives the file the same owner, and the library follows (stafeto-design#344, with the relibc part of step 6). `shmat` takes no address. `semtimedop`, `msgctl` info commands and `IPC_INFO` are not provided. The worst step of the service for these calls is 14,702 ticks of B = 20,410 (`cargo xtask posix-ipc-steps`): the step that hands on the units of thirty waiters of a process that was killed holding them, one wake in each step; the longest call is 13,492, BROKER_JOBS 5,441. The file service's IPC_JOBS takes 5,080 ticks with a wait in `send` of at most 24,465 of CALL_WAIT_MAX 48,000 (a turn of its maintenance), and the portions of a removal of a segment's file 15,937 at most. A tree of processes has room for about 66 threads, and the paths that count the waiters scan the whole table of 128 places whatever its fill. For the socket calls the worst step is 10,021 ticks with eight operations waiting at one socket and a tree at its 28 sockets (`cargo xtask posix-sock-steps`).
- **Names, metadata and the file service (review of E3-1).** (1) The operations on names and metadata (`rename` to `utimensat`, `ftruncate`, `statvfs`, `fchdir`, `realpath`) never return EINTR: after a handler the operation goes on, with any SA_RESTART, and ends once. (2) `fchdir` and the spawn action Fchdir: EACCES when the caller has no search permission in an ancestor of the directory, ENOENT for a removed directory with a live descriptor, ENAMETOOLONG for a canonical path above 511 bytes. (3) `posix_spawn` with POSIX_SPAWN_RESETIDS runs the file actions and the search of PATH in the parent, and checks permissions with the caller's real IDs in a check of its own before the action (a window lies between the check and the open). (4) A symbolic link to a virtual name of the terminal (`/dev/tty`, `/dev/console`, `/dev/ptmx`, `/dev/pts/N`) is not followed: ENOENT in every operation through the link. (5) `chown` clears S_ISUID and S_ISGID of a non-directory also for a privileged caller and when both IDs are -1 (implementation-defined); a directory keeps the bits. (6) `link()` does not follow a symbolic link in path1, as `linkat(..., 0)` (implementation-defined). (7) Sticky bit: removing and renaming are allowed to the owner of the file, the owner of the directory and a privileged caller; the variant "file is writable" is not taken. (8) `ftruncate` of a description without write access is EBADF, of a directory EISDIR. (9) `posix_getdents` accepts any flags and `d_type` is always known. (10) A name operation answers EAGAIN when nested handlers have taken all 16 places of the current thread. (11) `chmod`, `chown`, `utimensat`, `fchmod`, `fchown` and `futimens` on a virtual name of the terminal are EROFS. (12) `faccessat` and the permission checks of virtual names use no supplementary groups. (13) `statvfs` and `fstatvfs` of a terminal name, a pipe and the console give zeros with `f_namemax` 255 and a block size above zero. (14) RLIMIT_FSIZE and SIGXFSZ act on `ftruncate`, `truncate` and `write` only where the file grows: a shrink or an equal size passes also for a file above the limit, as on Linux. (15) TCOFLUSH and TCIOFLUSH flush the queue of the terminal service, the software queues of the UART driver and the hardware TX FIFO of the PL011 (LCR_H.FEN is cleared after the RX FIFO moved into the input ring); the character in the shift register goes out on the line, a byte received in the window of four register writes is lost, with a full input ring the FIFOs stay and the tail up to the FIFO depth goes out on the line, and virtio-console flushes the software queues only (bytes handed to the device stay until it confirms). (16) A file made with a mode that has S_ISGID loses the bit when its group (inherited from a directory with S_ISGID) is neither the creator's group nor one of the creator's supplementary groups and the creator is not privileged; a directory keeps the bit by inheritance. (17) A blocking open of a FIFO is not refused with EAGAIN when the eight places for open ends are full: the ticket stays in the phase of the grant and the library repeats the attach every millisecond, so the order of waking is not FIFO for the opens that overflowed. (18) `mknod` and `mknodat`: S_IFIFO makes a FIFO (umask, errors as `mkfifo`); S_IFREG, S_IFDIR, S_IFCHR, S_IFBLK, S_IFLNK, S_IFSOCK and type 0 are EPERM, a mode with an undefined type EINVAL (implementation-defined). (19) {LINK_MAX} is 384, the share of names of one account (DENTRY_SHARE) for all its files: the service sets no length of the list of links of one file and returns no EMLINK, and with other names in the account a link fails with the error of the quota before 384. (20) {OPEN_MAX} is 1 024 (see Descriptors); `io/dup3-clofork-fork` of os-test passes. (21) The relibc fork carries these changes of general code for the main branch of Redox: `convert_octal` is `convert_integer(s, 8)` so that `strtoul` and the other `strto*` accept an octal number without a leading zero; `pthread_create` answers EAGAIN when `Tcb::new` fails (POSIX.1-2024 lists no ENOMEM); `Pal::dup3` takes O_CLOEXEC without O_CLOFORK and, when `fcntl` fails, leaves the copy in `fildes2` with the old `fildes2` closed; `detect_base` parses "08" and "09" with base 0 as 0 ending at the second digit; the removal of a directory by `remove` on Redox follows redoxfs, which answers EISDIR. (22) PL011 on a real chip (review of stafeto#117): the manual forbids a change of LCR_H while the transmitter is busy, so a pause of one character follows CR=0, and LCR_H is written with the constant WLEN_8 (PARENB and CSTOPB would need a read-modify-write). The wait for a FIFO is a poll every millisecond without a queue, so a late opener can overtake a waiting one (stafeto-design#266).
- **Message catalogs, crypt, getdate, dlopen.** `catopen`, `catgets` and `catclose` read the catalog format of the BSDs, which `gencat` (FreeBSD's, in the images of os-test only) writes; NLSPATH and the default `/usr/share/nls/%L/%N.cat` are searched. `crypt` knows the traditional DES (musl's code of FreeSec), `setkey` and `encrypt` the same cipher. `getdate` follows DATEMSK. `dlopen(NULL)` answers a handle of the program, `dlsym` finds no symbol by name in a statically linked program, and every other `dlopen` fails with a message that says so.
- **Complex functions (Zh).** The functions of `complex.h` are computed in binary128 and the double and float ones round that value once, so they are correct to the last bit except in about one case in 2^60, with the special values of C11 Annex G (`openlibm/src/stafeto_cplx.h` in the relibc fork). They run at the speed of the software binary128 arithmetic; the floating-point exception flags are those of the intermediate steps.
- **Robust mutexes (Zh).** A thread that ends holding a robust mutex leaves it unlocked and marked: the next `pthread_mutex_lock` returns EOWNERDEAD with the mutex held, `pthread_mutex_consistent` repairs it, and an owner that unlocks it unrepaired makes it ENOTRECOVERABLE. A thread holds at most 64 robust mutexes at a time (EAGAIN beyond). A process that ends while one of its threads holds a robust mutex that lies in shared memory leaves it locked.
- **Typed memory and device control (Zh).** `posix_typed_mem_open`, `posix_typed_mem_get_info`, `posix_mem_offset` and `posix_devctl` are declared and answer that no typed memory object and no device control command exists (ENOENT, ENODEV, EACCES and ENOTTY); `_POSIX_TYPED_MEMORY_OBJECTS` stays unclaimed.
- **File status flags (Zh).** `fcntl(F_GETFL)` on a file of the RAM service returns the access mode and O_APPEND the file was opened with (it gave O_RDWR before); O_NONBLOCK of a file is not recorded. A request for cancellation that came while the state was disabled or before the asynchronous type acts when the thread enables the state or sets the type.
- **Descriptors (Zh).** {OPEN_MAX} is 1 024: the layer's table and the default of RLIMIT_NOFILE say so (the soft limit may be lowered, and the limit cannot be raised above the table), and `dup2`, `dup3` and `F_DUPFD` take numbers up to 1 023. The first 64 numbers lie in the table itself and the others in pages of the heap that a call maps when a number asks for one (EMFILE when there is no memory for the page). `sysconf(_SC_OPEN_MAX)` answers the limit of the process, at most 1 024. `exec` and `posix_spawn` carry at most 64 descriptors to the new image (numbers up to 1 023) and answer ENOMEM before any change when more stay open without FD_CLOEXEC; a `fork` copies the table and the sockets of the network service in portions of 64 descriptions. The services keep their own shares: the file service holds 32 open descriptions for a session and the pipe service 32 ends, so `open` and `pipe` answer EMFILE when the share of their service is full, whatever the table still has free; duplicates of one description cost no share. `poll` and `select` take up to 1 024 descriptions: up to 64 go in Watches of 32 (pipes) and 16 (terminal), whatever the numbers of the descriptors up to 1 023, and more go through the engine of epoll (see Watches and epoll). `SIGSTKSZ` is 48 KiB (was 32 KiB): a handler on the alternate stack may start a program, and the layer's frames for the table need more than 32 KiB with the signal frame.
- **Watches (Zh, step 6).** `poll`, `ppoll`, `select` and `pselect` take up to {OPEN_MAX} (1 024) descriptions. Up to 64 elements go the direct way: the layer splits the set into Watches of 32 for the pipe service and of 16 for the terminal service (the elements may repeat a description, and copies of a descriptor cost no share). More than 64 go through the engine of epoll (stage P4a-2): a temporary interest set of the network service holds the sockets (one record by level for each descriptor number, the events of repeated numbers joined, in batches of EPOLL_SET), the other descriptors (at most 64, EAGAIN past that, which POSIX allows for a failed allocation of internal data) go the direct way, one wait takes both, and the set is dropped at the end. A call pays the batches of EPOLL_SET each time, so a program that needs speed uses `epoll`. EAGAIN also answers a call when the session of the process has no free interest set (4 for a process). An `nfds` above {OPEN_MAX} is EINVAL for `poll`. Descriptors that are none give EBADF first for `select` and POLLNVAL for `poll`.
- **epoll (P4a-2).** `epoll_create1`, `epoll_ctl` and `epoll_pwait` (with `epoll_create` and `epoll_wait` built on them) work on pipes, FIFOs, terminals, the console and the sockets of the network service (and AF_UNIX sockets, which are descriptions of the pipe service). The records of sockets live in an interest set of the network service, which keeps a list of the records that are ready (by level a record returns to the tail of the list after a report, by edge it reports when a frame brought bytes or a new state, or an event it did not carry at the last report is back, and EPOLLONESHOT turns a record off until `EPOLL_CTL_MOD`) and tells the waiting operation of the set from its step of waking; the user's data word lives in the layer. A record by edge of a pipe, FIFO or terminal reports a level again after a read, write, receive, send or accept on that descriptor ended with EAGAIN, which is the contract of epoll by edge: wait for the event after EAGAIN. EPOLLPRI is never reported, EPOLLRDHUP follows a FIN of the peer, a reset of the peer is EPOLLERR once and `SO_ERROR` ECONNRESET. A record of a pipe, FIFO or terminal that another thread adds during a wait is seen from the next wait (a socket added meanwhile wakes it). `epoll_pwait` answers at most 64 events a call (more in `maxevents` is cut), and a signal ends it with EINTR whatever SA_RESTART says. Limits: 8 instances for a process (EMFILE), 1 024 records for an instance, 64 of them for descriptors that are not sockets, 16 records of different sets on a socket and 4 sets for a process (ENOSPC, ENOMEM). Deviations from Linux: (1) an epoll descriptor is closed at `exec` whatever its flags, and after a `fork` the child's copy answers EBADF to `epoll_ctl` and `epoll_wait` and closes without touching the parent's set (the set belongs to the parent's session); (2) a record lives while its descriptor number with the same generation lives: `close`, `dup2` onto the number and `exec` with FD_CLOEXEC take it away even if the description has another descriptor (Linux keeps the record while the description lives); (3) an epoll descriptor in an epoll gives EINVAL (Linux allows nesting); EPOLLEXCLUSIVE is accepted by `EPOLL_CTL_ADD` with the bits Linux allows with it (EINVAL for MOD and for other bits) and wakes one of the sets that wait on the socket (the first whose instance has a thread in the wait; when none waits, every set gets the event), as in Linux; EPOLLWAKEUP is ignored; (3a) two numbers of one socket cannot be in one instance (the second ADD is EEXIST; Linux keys the record by the pair of description and number); (4) `fstat` of an epoll descriptor gives the mode 0600 with no file type; `read`, `write` are EINVAL, `lseek` ESPIPE, SCM_RIGHTS EOPNOTSUPP, and a poll of it reports POLLERR. `ioctl(FIONREAD)` (SIOCINQ) of a socket of the network service answers the bytes of a stream waiting to be read or the length of the next datagram.
- **Complex at the limits (Zh).** The long double functions of `complex.h` overflow early near LDBL_MAX (their formulas form 1 +- u and call hypotl); the double and float ones, computed in binary128, do not.
- **Numbers (Zh).** `strtod` and `strtof` convert a decimal constant whole with the rounding of the whole constant and set ERANGE on overflow and underflow to zero; `wordexp` prints its words with `printf` (a word `-n` stays); a signal of `aio` with SIGEV_SIGNAL carries `sigev_value` (`sigqueue`). A timed wait (`sem_timedwait`, `pthread_mutex_timedlock`, `pthread_cond_timedwait`) whose absolute deadline lies past a whole second of the clock ends at the deadline (it ended a second late before).
- **Asynchronous I/O and file transfers (Z).** `aio_read`, `aio_write`, `aio_fsync`, `aio_cancel`, `aio_suspend`, `lio_listio`, `aio_error` and `aio_return` run on threads of the library (`src/header/aio` of the fork): the requests of one descriptor are carried out in order by one thread, which ends with the queue, and `{AIO_MAX}` and `{AIO_LISTIO_MAX}` are 128 (`sysconf`; a request past them is EAGAIN). `_POSIX_ASYNCHRONOUS_IO` and `_POSIX_FSYNC` are claimed (202405). A request that has not begun is cancelled (ECANCELED); the one that runs is AIO_NOTCANCELED. A bad descriptor is the error of the request (`aio_error` gives EBADF), except for `aio_fsync`, which fails at once. `aio_error` answers EINVAL for a control block no request was made with and for one whose end `aio_return` took; the second `aio_return` is -1 with EINVAL. A write to a descriptor opened with O_APPEND appends. The notices are SIGEV_SIGNAL with `sigqueue` (the real-time signals of the next paragraph apply) and SIGEV_THREAD in a thread of its own; a list started with LIO_NOWAIT notices once when its last request has ended. A child of `fork` has no requests of its parent. `{_POSIX_PRIORITIZED_IO}` is not claimed and `aio_reqprio` must not be negative. A process has a stack of 64 KiB, so a test that keeps a thousand control blocks on it ends with a fault. `write`, `pwrite`, `read` and `pread` of a regular file take all that is asked, however many messages of the file service it takes (a message holds a little under a kilobyte; a failure after a part gives the count of the part; a pipe, a terminal and a socket return what one call gives). `open` accepts O_SYNC, O_DSYNC and O_RSYNC; the RAM service has every write done when the call returns, and `fcntl(F_GETFL)` does not report them. A write of a regular file longer than one message is not atomic: another process sees a part of it, and with O_APPEND the parts of two writes interleave. `_POSIX_SYNCHRONIZED_IO` is not claimed, and `pathconf(_PC_SYNC_IO)` says -1 to agree. `lio_listio` with more entries than `{AIO_LISTIO_MAX}` is EINVAL. `mq_close` takes off only a registration that its own process made, so a child of `fork` that closes its copy of the descriptor leaves the parent's. The buffer of an AF_UNIX datagram socket is never set below one datagram with the longest sender's address (932 bytes) and its default holds two such datagrams (1,864 bytes; the figures above are those of an unnamed sender).
- **Timers with a function in a thread (Z, stafeto-design#302).** `timer_create` with SIGEV_THREAD makes a timer kept by the library: a helper thread of the timer sleeps until the expiry and runs the function in a detached thread of its own with `sigev_notify_attributes`; no signal number is used. The clocks are CLOCK_REALTIME and CLOCK_MONOTONIC, an absolute CLOCK_REALTIME time is turned into the monotonic scale when the timer is armed, and `timer_getoverrun` counts the periods that passed while the previous notice was due. A child of `fork` does not have the timer.
- **Goal I, threads, signals and scheduling.** A thread stack made by `pthread_create` always has a guard of `guardsize` bytes (one page by default) unless the application gave the stack: the guard is a hole in the layer's room just below the stack (no memory object, no entry in the kernel's table, no frame), so a write below the stack is a translation fault (SIGSEGV), the guard costs no quota whatever its size, and 63 threads each with a guard fit the table of 128 mappings. A `pthread_create` that finds no memory for its stack collects the stacks of threads that ended and tries once more. `pthread_join` and `pthread_detach` of a thread that was joined say ESRCH, of a detached one that ended EINVAL; a thread the layer started itself is taken as live. The waiters of a named semaphore stand in the pipe service in the order of the priorities of their threads (the greater first, the older first among equals) and a `sem_post` hands its unit to the first of them (the value stays 0, so `sem_getvalue` and `sem_trywait` do not see a unit that is a waiter's, and `sem_wait` waits only at 0), one wake a call; a waiter that leaves holding a unit (a signal, a deadline, the end of its process) hands it on in a step of the service, and waiters of a semaphore that went are told one in each step; they take their places in the pool of 128 waiting operations of the service (96 for a tree of processes). A wait that finds the pool used up (EAGAIN) is asked again every 2 ms until its deadline: it polls, and keeps no order meanwhile. Signals: `pthread_kill` gives SI_TKILL (a `raise` that takes a signal of the same number at the same moment may get its code: the mark is one bit a signal) (-6, Linux's code for a signal to one thread; XSH 2.4.3 leaves the code of such sources to the implementation, and it differs from the listed ones) with the PID and UID of the process; `raise` and `abort` give SI_USER with the same PID and UID, which XSH 2.4.3 lets `raise` do and Open POSIX `sigwaitinfo/6-1` expects; SIGQUEUE_MAX (32) is counted at the sender: the occurrences of `sigqueue` that a process sent and that still wait at their receivers (on a page or queued), so two senders may put 32 each at one receiver, one sender is refused the 33rd wherever it goes, and a receiver that takes one gives the sender a place back; the pool of the service (512 occurrences for all processes) is the limit of the system and its end is EAGAIN as well; all 64 bits of a signal set are signals; an interval below 1 ms of a timer is kept as set and looked at no more often than every millisecond. `setitimer` on ITIMER_VIRTUAL and ITIMER_PROF is the library's, counting the processor time of the process; a zero setting takes the timer off with its interval. A process that sleeps is `S` in `ps` and `top`. Two tests of Open POSIX (`aio_read/9-1`, `aio_write/7-1`) keep 1,024 `struct aiocb` on a stack of 64 KiB: the build makes the array static (`SOURCE_FIXES`). SCHED_OTHER stands at the level `top - 32` of a process only when its ceiling is above 32, else at the ceiling; the image of the test runner has priority 35 and ceiling 36.
- **Executable memory (`mmap` and `mprotect`).** `PROT_EXEC` is allowed for private mappings, anonymous and of a file; the right `x` of the file is not checked (POSIX does not ask for it, and a program can read a file into an object of its own and run it). `PROT_EXEC` alone and with `PROT_READ` both give read and execute. `PROT_WRITE | PROT_EXEC` is ENOTSUP in `mmap` and `mprotect`: no page is writable and executable at once (the kernel has no such access and SCTLR_EL1.WXN forbids it), so a program that generates code writes it through a writable mapping and calls `mprotect` to `PROT_EXEC`, and the kernel cleans the caches at each such change. `MAP_SHARED` with `PROT_EXEC`, and `mprotect` to `PROT_EXEC` of a part of a shared mapping, is ENOTSUP (the shared object goes to other processes and to the loader of a forked child without the right to run code); `mprotect` to `PROT_EXEC` of a read-only part of the program's image is EACCES. A forked child gets the executable parts of the parent as copies mapped without the right to write, and the pages of the parent that were writable as objects without the right to run code, so in a child `mprotect` of such a copy back to writable, or of a writable copy to `PROT_EXEC`, is EACCES (the correction is in the loader, planned for 0.2.1). A reference to a whole page past the end of a mapped file is SIGBUS with `BUS_ADRERR`; Open POSIX `mmap/5-1`, `mmap/11-2` and `mmap/11-3` pass.
- **Goal I, other changes.** A word in a mapping other processes share (`MAP_SHARED`: a semaphore, a mutex, a condition, a barrier or a lock of `pshared` kind in a shared segment) is waited on in the pipe service under the key of its object (the file for a file or `shm_open`, the maker's PID and a count for anonymous memory) and the offset of the word, so that a wake from any process reaches it: the waiters wake in the order of their priority, the older first among equals, and a waiter that leaves with a wake (signal, deadline, end of the process) hands it on. A word whose object has no key, and every wait once the table of 128 waiting operations is full, look at the word every millisecond. `sem_post` wakes one waiter, and none when nobody waits. There is no inheritance of priority between processes (a `PRIO_INHERIT` mutex in shared memory does not lend its level), and a robust mutex in shared memory does not become `EOWNERDEAD` when its holder's process ends. The option THREAD_PROCESS_SHARED is claimed (`_POSIX_THREAD_PROCESS_SHARED` and `sysconf(_SC_THREAD_PROCESS_SHARED)` say 202405); the owner word of a mutex holds the PID in its high bits and the thread number in its low eight, so that an error-checking or recursive mutex of a shared page tells the threads of two processes apart. `sem_wait` and `sem_timedwait` fail with EINTR when a handler without SA_RESTART ran during the wait. The state of a process in `/proc/<pid>/stat` and `status` is `S` when it has run no ticks since a sample taken at least 2 ms before (any reader of the list takes samples), else `R`. A condition variable made with a monotonic clock in its attributes waits for absolute times of that clock. `pthread_atfork` takes 1,024 handlers of a kind (ENOMEM beyond), `PTHREAD_KEYS_MAX` is 1,024 (EAGAIN beyond), `PTHREAD_STACK_MIN` is 65,536 and `sysconf(_SC_THREAD_STACK_MIN)` says so. `gettimeofday` is `clock_gettime(CLOCK_REALTIME)`. `strftime` knows `%c`, `%G` and `%g`, writes `%U`, `%V` and `%W` with two digits, and `%C` is the century. The headers have `ucontext.h`, `sys/vfs.h` (`statfs` over `statvfs`, the type of the file system 0), `si_band`, `si_fd`, SIGPOLL, `POLL_IN` and its kin, and `POSIX_MADV_DONTNEED`; `_POSIX_SPORADIC_SERVER` and `_POSIX_THREAD_SPORADIC_SERVER` are -1. The runner of Open POSIX gives a test 60 s (120 s for functional and stress tests; timer_settime 5-3 sleeps 150 s by design and has 240 s), starts the tests with `/proc`, `/bin/sleep` and `/bin/ls`, and the processes of the tests have a quota of 1,280 pages.
- **Shared mappings of files.** The object of a `MAP_SHARED` mapping of a file is one for all processes. A process that asks while another makes the object waits in the process service until the maker has read the file or has gone (it ends, or detaches); the first of several waiting asks of a key whose maker went becomes the maker. A second thread of the maker's own process waits as well. The wait is bounded by the maker's progress (the reading of the file, the preemption of the maker by higher levels and, with no limit, the stop of its process by SIGSTOP, which the wait does not see), without a raise of the maker's level: map files before the real-time work starts. Entries of the service: 16 objects; waiting asks: 64, a process holds 4. A writable `MAP_SHARED` mapping that finds no place (the table of objects full, no place to wait, the vouching of the file service refused after the wait) fails with ENOMEM; a mapping that only reads goes on with an object of its own. Signal handlers do not run in an `mmap` of a shared file between its vouching and its Put (a critical section of the layer). The layer writes a shared mapping back through a description it pins without a number (up to 16 files a process; the mappings of one file share a pin, counted by the mappings that hold it, and a mapping that writes back gets a pin of a description open for writing): the pin is outside the numbers 0 to 63, so `fcntl`, `closefrom`, `dup2` and the enumeration of numbers never meet it, and a program may use all 64 numbers while 16 files are mapped. A pinned description keeps one of the 32 places of the session of the RAM service after its numbers close, so a program with 16 files mapped and closed opens 16 more different files; the list of a Clone never exceeds 32. The 17th file mapped shared at once fails with ENOMEM, as Linux answers at the limit of mappings and as the layer answers when the process service has no place for another object; POSIX names EMFILE for that limit, which a program could take for a full table of numbers. `fork` gives the child the pins with the memory, `exec` drops them. A record lock goes with the close of the last number of a pinned description, as with any close; a lock of an open file description lives until the last mapping goes.
- **Real-time signals (I).** The layer has the signals 1 to 64 and the real-time ones from SIGRTMIN (35) to SIGRTMAX (64); `_POSIX_REALTIME_SIGNALS` is claimed (202405) and `sysconf(_SC_SIGQUEUE_MAX)` is 32. The process service keeps the first occurrence of a signal on the page of the process and queues the others behind it in the order they came (a pool of 512 for all processes, 31 behind the page for one): occurrences of `sigqueue` for any signal, and of a real-time signal however it was sent (`kill`, a timer's overrun excepted). A thread that takes an occurrence off the page asks the service for the next (`Page::more`, `account_op::SIGNAL_NEXT`). A `sigqueue` that finds 32 occurrences of `sigqueue` waiting for the process is EAGAIN; `kill` drops the occurrence of a real-time signal that finds the queue full. A process that ignores a signal loses the queue of it at the next signal. `raise` and `pthread_kill` of a real-time signal that waits already for the thread go on as a signal of the process (Open POSIX `sigwait/2-1` raises a real-time signal twice and takes two occurrences; the second comes with SI_USER and another thread may take it), so another thread may take them. The occurrences wait for the process; a thread's pending signals keep one place for each signal. A timer's signal does not queue (the overrun counts). `sigwaitinfo` and `sigtimedwait` give a signal of a thread (`raise`, `pthread_kill`) with `si_code` SI_TKILL (`pthread_kill`) or SI_USER (`raise`) and the process's PID and real UID. A signal of the set that is not blocked is not refused, and a signal in the set that a handler could take goes to the wait (`sigwait` of an unblocked signal returns it). PID 1 has no record: `kill` and `sigqueue` to it are allowed to a superuser and EPERM for anyone else, and nothing happens.
- **Alternate signal stack and faults (step 5).** The handlers that run off the alternate stack while a dispatcher frame is live at its top form a chain of levels, so a long jump out of a nested handler takes off only the levels it leaves (#287), and a child of `fork` made in such a handler gets the cut range of the kernel (#286). The process ends by SIGSEGV when a delivery on the alternate stack finds less than 4 KiB left under it, or finds the stack already overrun (a handler of the stack is live and the caller lies below its range, whatever the place of the new handler; the interrupted code of an entry below the range counts as well) (#293). The frame of the distributor (1,904 bytes) and the frame of the delivery are built before these checks and may lie below the range: the process never goes on after the overrun, but the write below the range happens first (a refusal of the kernel to build the entry frame without room is an open task). A nested handler of SA_SIGINFO that `raise` calls costs about 13 KiB, so a program that nests handlers on an alternate stack needs about 13 KiB for each level; a handler that moves to another stack (`swapcontext`) and gets a signal there is taken for an overrun. MINSIGSTKSZ (12,288) holds a handler with a 2 KiB array (#289); the delivery takes about 7.1 KiB of it and RESERVE is 4 KiB, so the margin is about 1 KiB.  A `fork` made in a handler of a thread that is not the main one returns from it in the child (#291). A misaligned stack pointer is SIGBUS with BUS_ADRALN and `si_addr` equal to it (the Cortex-A53 and QEMU TCG may not trap it; Apple's HVF does); a trapped floating-point exception with no valid cause bit (TFV clear) is SIGFPE with FPE_FLTINV (the Cortex-A53 has no trapped floating-point exceptions, so class 0x2c does not come there) (#292).
- **Absolute times (I, stafeto-design#296).** A CLOCK_REALTIME timer set with TIMER_ABSTIME follows a `clock_settime`: the process service moves the deadlines of such timers of all processes by the step of the calendar (`timer_op::CLOCK_STEP`, told by the layer after a successful `clock_settime`; only a superuser may tell it), and a timer that comes due is due at once. A sleep on an absolute time of CLOCK_REALTIME (`clock_nanosleep`) looks at the calendar every 100 ms, so that a set ahead or back moves its end by at most that. The absolute deadlines of `mq_timedsend`, `mq_timedreceive`, `sem_timedwait`, `pthread_mutex_timedlock` and `pthread_cond_timedwait` on CLOCK_REALTIME are still turned into the monotonic scale when the wait begins: a `clock_settime` while they wait does not move the deadline (stafeto-design#339). CLOCK_REALTIME starts at the time of the host where the machine has a source for it (generation 0): the PL031 of QEMU `virt` and HVF, read by the clock service when it starts, or, on Apple VZ, which has none, the time `tools/vz-run.swift` writes into the file `boot-time` of a copy of the boot image (`--time SECONDS` sets another); a machine with neither starts at 2026-01-01 00:00:00 UTC. The address of the PL031 is the fixed one of `virt` (0x0901_0000) in the table of init, since the kernel gives no device tree to the programs.
- **Processor time (I, stafeto-design#348).** `_POSIX_CPUTIME` and `_POSIX_THREAD_CPUTIME` are claimed. CLOCK_PROCESS_CPUTIME_ID, CLOCK_THREAD_CPUTIME_ID, the clock of a thread (`pthread_getcpuclockid`) and the clock of another process the caller may signal (`clock_getcpuclockid`, read from the process service) are clocks to read. A timer on such a clock (`timer_create`), and ITIMER_VIRTUAL and ITIMER_PROF of `setitimer` are kept by the library, with a helper thread that looks at the clock and sleeps by the fourth of what is left (at least a millisecond): the signal comes within about a millisecond of the time, and the helper thread counts among the threads of the process. A timer of this kind that gives a signal has a place in the timer table of the process service, with no deadline there: the helper tells the service of each expiry (`Timer FIRE`, the expiries it counted since its last word), and the service sends the signal as for its own timers, with `si_code` SI_TIMER and the value of the event, merged with a signal of the timer that waits, and counts the overrun that `timer_getoverrun` reads. The place counts in the 32 timers of the process, so `timer_create` on such a clock may be EAGAIN, as on any other. A child of `fork` has none. The kernel tells the time of a thread in the kernel from the rest (`stafeto_cpu_system_ns`), but the CPU clocks and the timers on them count both, so ITIMER_VIRTUAL and ITIMER_PROF count the same time; `clock()` is the processor time of the process. A `pthread_condattr_setclock` with a CPU-time clock is EINVAL. The interval of a periodic timer is kept as set (it was raised to a millisecond): the service looks at a timer with an interval below a millisecond once in a millisecond and counts the expirations in between into the overrun; while the signal of a timer waits, `timer_getoverrun` shows the count of the signal delivered before it, and for a signal that is ignored by default and has no handler (SIGCHLD, SIGCONT, SIGURG, SIGWINCH) the expirations after the first join its overrun.
- **Size of the window.** The terminal answers `TIOCGWINSZ` with the size it holds (0 by 0 until it is told, which BusyBox reads as unknown) and `TIOCSWINSZ` stores a size; a size that differs from the old one sends SIGWINCH to the foreground process group, as on Linux (`stty size`, `stty rows N cols M`, `resize`). The host tells the console its window with a report in the input bytes: GS (0x1D), `W`, the rows, `;`, the columns, GS (`services/tty/src/window.rs`). The serial line of QEMU (the PL011) and the Virtio console of VZ carry no size beside the bytes (QEMU gives no `VIRTIO_CONSOLE_F_SIZE`: its configuration holds zero for columns and rows), so `cargo xtask ash-shell` and `tools/vz-run.swift` send the report at the first prompt and with every SIGWINCH of the host. The console reader takes the report out before the line discipline sees the input; a typed Ctrl-] (the same byte), or the start of a report that does not finish, is held for 75 ms and then reaches the reader as typed, and a report with a zero or a size past 65535 stays input as it came.
- **Goal I2, the shell.** `putenv` and `setenv` put a new variable at the end of the list `environ` holds when a program has ended the list early with `environ[0] = NULL` (the idiom of `clearenv`, which BusyBox's ash uses before it runs an applet in its own process), so `env A=1 env` shows `A=1` when the environment of the shell was not empty at the start; the list had kept the new variable behind its end. `mkstemp`, `mkostemps`, `mkstemps` and `mkdtemp` end at the first try that fails for a reason other than EEXIST and leave that errno (ENOENT for a directory that is not there); they gave EEXIST after a hundred tries. `abort` prints no line of the log before SIGABRT. `gettimeofday` stays `clock_gettime(CLOCK_REALTIME)` in microseconds, and htop is built with no `-DHAVE_CLOCK_GETTIME`. The image has `/root` (mode 0700), the home of root in `/etc/passwd`, where htop keeps its settings. The terminal line of a Ctrl-C that comes between two reads of readline: the signal reaches the shell, and readline notes it at its next key, as on Linux (the probe sends the key again).
- **Image files (I2, stafeto-design#380 to #382).** The files of the boot image have the time of the build as their access, modification and change times (SOURCE_DATE_EPOCH when it is set, else the time of the build; the table `rootfs` carries it), where they had the time of the start. The utilities of BusyBox in `/bin` are symbolic links to `busybox` (`ls -l /bin/cat` shows `cat -> busybox`, 7 bytes, mode `lrwxrwxrwx`, one link), where they were hard links of one file with its 3 MB size and a count of 91; `argv[0]` of a utility is the name of the link, as with BusyBox elsewhere. A listing of a directory (`readdir`) names a symbolic link of the image with `d_type` DT_LNK. The RAM service (`/libexec/ramfs`) and `login-probe` (`/libexec/login-probe`) are out of `/bin`.
- **Login shell (I2).** `ash` in the shell image is a non-login shell (`-l` is gone from its command line), so `/etc/profile` is not read; getty sets `TERM` before it starts the shell. Checked by Opus (stafeto-design `tasks/2026-10-18-i2/review.md`).
- **CPUs (stafeto-design#415).** `sysconf(_SC_NPROCESSORS_CONF)` and `_SC_NPROCESSORS_ONLN` give the CPUs the kernel runs (1 where it runs one; they were -1). `sched_getaffinity` gives the CPUs the process may use (the mask the kernel gave the process, which is its record's in init's table, within those that are up; the shell and its commands stand on CPUs 0 and 1, `nproc` says 2 on four CPUs, and the mask of a child of `fork`, `posix_spawn` and `exec` is its parent's) and `sched_setaffinity` writes the process's mask to its page within the kernel's mask (EINVAL when none of the CPUs it names is in it): the threads the process makes afterwards and the image of its next exec start on a CPU the mask names, and a thread that runs stays on its CPU, because the kernel moves no thread (the mask of a child is its parent's, an exec keeps it). The mask is the process's: `pthread_setaffinity_np` and `pthread_getaffinity_np` read and write it whichever thread they name, and `sched_setaffinity` of another process is EPERM (ESRCH if it does not exist). `sched_getcpu` is new, and `CPU_COUNT` counts the whole set. The process service puts the main thread of every new image (spawn, fork and exec) on the least busy CPU its mask allows, where a CPU is busy when it was awake a quarter of the last window of 10 ms (its time asleep, read from the kernel once per CPU at the close of a window, so that the step does not grow with the number of processes) and each image put on it in the last two windows counts as one more, and a thread starts on the CPU of its creator. `/proc/stat` has a line `cpuN` for each CPU from the kernel's count of its time (user, system, idle; the line `cpu` is their sum), `/proc/cpuinfo` has a record for each CPU, and the field `processor` of `/proc/<pid>/stat` is the CPU of the process's main thread. The listing of `/sys/devices/system/cpu` names the CPUs that are up, which htop counts (BusyBox is built without long options, so `nproc --all` says what `nproc` does). BusyBox `nproc` and `taskset` are in the shell image. The POSIX processes pay for their threads from a share of the process service (768 thread numbers and 6,144 timers in the images): `pthread_create`, `fork` and `posix_spawn` say EAGAIN when it is used up, and the services and drivers of init, which have no part in it, go on.
- **Step 6, part 1 (relibc).** `exit` flushes and locks every stream with something in its write buffer before it ends the other threads, so a line is never torn and `exit` itself never ends a thread inside a write with the lock of its stream; a stream with nothing to write is left alone (a thread that waits in a read of a stream for reading and writing does not hold the exit); a flush of a stream that `fclose` closed writes nothing. Risks of this exit: it waits for a thread that is blocked in a write under the lock of a stream (a full pipe, a long call between `flockfile` and `funlockfile`); a thread cancelled by `pthread_cancel` inside a write of stdio dies with the lock of its `FILE` (the write of the layer is a cancellation point, relibc's stdio has no cleanup handlers), and then every later output to that stream and the `exit` wait for good; a program that holds `flockfile` of one of its streams and calls `fopen` or `fclose` while another thread is in `exit` can deadlock with it (concurrent with `exit`). The child of `fork` gets the locks of all open streams free, so its `exit` does not wait for a thread of the parent. `fmemopen`, `open_memstream` and `open_wmemstream` keep their content in memory of the process behind a descriptor number no file has: `fileno` of them is -1 (EBADF) and no file service or space is used. `getlogin_r` reads `/var/run/utmpx` by itself, so the walk of the caller with `getutxent` keeps its place. `syslog` without `/var/log/messages` loses the message unless LOG_CONS sends it to `/dev/console`. `execvp`, `execlp` and `posix_spawnp` run a file with execute permission that is no program with `/bin/sh` (`execv` stays ENOEXEC; the runner of os-test keeps its own fallback for `posix_spawn` with a path). `fork` takes the locks of the aio lanes and of the timers before the copy, and the child has no timers and no lanes. A real-time signal sent to a thread repeatedly (`raise`, `pthread_kill`) is a counter of that thread, with the code of the first occurrence (a repeat sent with another code, or racing with the take of the pending occurrence, may carry the code of the first). Two senders that send a real-time signal to a thread that has none pending at the same moment both set its bit, and one occurrence is lost (the queue of `pthread_kill` is the implementation's, XSH 2.4.1). An unlock of a PRIO_INHERIT mutex wakes one waiter, the others lend it their level.
- **Processes, `/proc`, files and the terminal (step 6, part 2).** The state in `/proc/<pid>/stat` and `status` comes from the kernel state of the thread that receives the signals of the process (the main thread while it lives, then the next live thread): waiting for a message or a reply, or parked, is `S`; ready or running is `R`. A process whose receiving thread has ended without handing the role over shows `S` while its other threads run. A file or directory of `/proc` is a description of the layer (no service holds it): the text is made at the open, a duplicate shares the offset, `fork` copies the description with the memory (the child's offset is its own from then on, where POSIX shares it), and an `exec` carries the node and the offset, once for each number (two numbers of one description no longer share the offset in the new image), and makes the text again at the first read (the content after an `exec` is new). An image built without `/proc` drops the numbers of `/proc` it inherits. `/proc/<pid>/task` lists a thread for each live place of the layer's table; the number of a thread is the PID plus the place (the main thread's is the PID), which can be the PID of another process, so the image's `/usr/local/etc/htoprc` hides the threads of htop. The state and the times of a thread other than the main one are the process's. RLIMIT_MEMLOCK lives in the process service and survives `exec`. A fork of a map needs an object in the child for each group of adjoining regions; the table of objects holds as many as the 128 pieces, so a map of the parent always fits. A fault on a page that `munmap` gave back is SEGV_MAPERR. The main stack of a program is the size its file asks for (`PT_GNU_STACK`, `-z stack-size`), 64 KiB at least and 8 MiB at most; RLIMIT_STACK does not limit it (the loader gets no limits of the record) and still reads 64 KiB. `fchdir` of the descriptor of a removed directory is ENOENT (Linux enters the removed directory; XSH lists no error for it). The wait of the terminal for a signal to a group is under its limit for groups of up to 32 processes (docs/non-preemptible-paths.md).
- **Known departures of the full Open POSIX run (release 0.2.0).** Two tests of `cargo xtask open-posix --full` do not pass and stay outside `tests/open-posix/pass.txt`. `stress/threads/fork/s-c1` gives the verdict "not scalable", which depends on how many forks the pool holds (stafeto-design#508). `mmap/10-1` ends with TIMEOUT after 86 s (stafeto-design#501). The fixes are planned for 0.2.1. `mmap/5-1`, `mmap/11-2` and `mmap/11-3` (executable mappings and SIGBUS past the end of a file, stafeto-design#384) are fixed in 0.2.0 and return to the list.
- **Servers (P4a-3).** (1) A second `listen` with a larger backlog builds the queue of a stream socket up to it (16 at most); a smaller one changes nothing. A SYN that finds the queue full is dropped without a reset and the client sends it again, as on Linux, so `connect` is not refused (the network service counts them as `syn_dropped`). A new SYN on the four of a connection that the server closed first (TIME-WAIT, no process holds it) ends that connection and is accepted when a queue takes it; the number of the SYN is not compared with the one the old connection expects (the stack does not give it), so an old duplicate SYN of the earlier connection can end the TIME-WAIT early. (2) `SO_REUSEPORT` (streams only, set before `bind`): up to 16 sockets of one port and one address, all of one effective user (EADDRINUSE for another user at any overlapping address or for a socket that did not ask; the option is set before `bind`, EINVAL after it); each has a queue of its own and the service names for a SYN the member that a keyed hash of the four picks among those that listen, or the next one when its queue is full; the stack gives the SYN to the first socket in LISTEN of the set of places and that may be a socket of another member of the group, so the spread follows the hash only roughly. Every `bind` brings the identity session of the process, which the process service vouches for. (3) `SO_LINGER`: a time of 0 makes the last `close` reset the connection; a time above 0 makes a blocking `close` of the last descriptor wait until the data sent is acknowledged or the time ends (a signal ends the wait, and the close is done). `SO_RCVTIMEO` and `SO_SNDTIMEO` (a `struct timeval`, at most 49 days) end a waiting `recv`, `accept`, `send` or `connect` with EAGAIN (EINPROGRESS for `connect`, which goes on); the values belong to the description, as on Linux. (4) `socket`, `socketpair` and `accept4` take SOCK_CLOFORK. (5) SCM_RIGHTS over AF_UNIX carries sockets of the network service, at most 4 in a message (ETOOMANYREFS for a fifth): the sender's session makes a pass for each socket (a copy of the service's channel that holds the description, may be handed on and has no right to send requests), the pipe service keeps the passes of the messages in flight, and the receiver's session adopts them as descriptors. The pipe service holds at most 32 passes at once and 8 for a root, a program with its children (ENOBUFS), a session of the network service 16 and the service 64; a pass is a handle with the right TRANSFER alone, which the service cannot copy. `recvmsg` with room for descriptors asks for them only when the table of handles of the process has room for four more; otherwise the bytes come, the descriptors go and MSG_CTRUNC is set. The room is looked at once, before the wait of a blocking receive: a thread of the same process that fills the table of handles meanwhile makes the reply with its handles fail, and the message is lost from the stream together with its bytes (the service cannot yet put it back). All the processes under one record of init (a shell and everything it starts) share the 8 places of a root, so a process of the tree that never reads takes them from its neighbours; roots are kept apart, inside a tree there is no isolation, and four roots with 8 each take all 32 places, so a fifth has no share of its own. `getsockopt(SOL_SOCKET, SO_STAFETO_PASSES)` (0x7350, a number of stafeto's, read only, on any AF_UNIX socket) tells how many passes the pipe service holds (the count of the whole service, which every process may read). A socket that goes with passes in flight lets them go in steps of the service, and the socket they stood for closes when the last pass has gone.
