# POSIX interface inventory

`cargo xtask coverage` compares exported names in relibc's `libc.a` and stafeto's `libposix_crt.a` with [POSIX.1-2024 System Interfaces](https://pubs.opengroup.org/onlinepubs/9799919799/functions/contents.html). It also preprocesses available headers for macro names and checks the [Base Definitions header inventory](https://pubs.opengroup.org/onlinepubs/9799919799/basedefs/contents.html). The command writes `target/measure/posix-coverage.tsv` and `target/measure/posix-headers.tsv`, and builds both archives when run without arguments. For an existing build, use `cargo xtask coverage --libc path/to/libc.a --crt path/to/libposix_crt.a`; relibc's sources are read from `source/` beside `sysroot/` of that `libc.a`.

A function that exists but answers ENOSYS on stafeto is a stub (availability `stub-enosys`) and does not count as covered. The stubs come from relibc's sources (`xtask/src/stubs.rs`): a platform method whose whole body is `Err(Errno(ENOSYS))`, a trait default that only calls stubs, and a public function that only hands its arguments to stubs. A public function is a stub when every call it makes is a stub (through `Sys::` or a function of relibc), with opening and closing a descriptor not counting, so `statvfs` (over its stubs) is found. A short list of stubs the reading misses (`mkdtemp`, `realpath`) is kept by hand in `xtask/src/stubs.rs`. A function that answers ENOSYS for some arguments only, or does more work around a stub, is not found. The summary prints the coverage as exported symbols plus header macros over the interfaces of each requirement level.

The checked-in [XSH inventory](../tests/posix/2024-xsh.tsv) records names, reference pages, headers, and option codes. The [XBD inventory](../tests/posix/2024-xbd-headers.tsv) records all 86 standard headers and their option status. Regenerate both with `python3 tools/posix-inventory.py --cache /tmp/posix-2024 --output tests/posix/2024-xsh.tsv --xbd-output tests/posix/2024-xbd-headers.tsv`. The extractor reads the official pages and keeps downloaded HTML in the requested cache directory. Its current extraction covers 701 distinct XSH reference pages, 1,241 names, and 1,035 names outside optional regions; XBD has 70 required headers. The inventory includes named objects such as `errno` and the `CMPLX` macros. Alternate XSH URLs can serve identical page content. The cached pages are omitted from the repository.

The extractor reconciles NAME and indexed SYNOPSIS declarations with the [alphabetical index](https://pubs.opengroup.org/onlinepubs/9799919799/idx/functions.html). This includes the `FD_*` macros and `_Fork`, and discovers the `va_arg` page omitted by the contents index. `getdate_err` is an XSI object: its declaration scope comes from XBD `time.h`, since XSH DESCRIPTION defines it without an option marker. The index retains historical links for `asctime_r` and `ctime_r`; Issue 8 Defect 1410 removes those functions, so they are explicitly excluded. Unexpected or unresolved index differences stop generation. Focused extraction tests run with `python3 tools/test_posix_inventory.py`; inventory and symbol/macro parsing tests run with `cargo test -p xtask coverage`.

An `exported-symbol` row has a linker-visible entry point. A `header-macro` row names a macro seen when compiling the listed header for AArch64. An `unresolved` row needs review for missing headers, preprocessing failures, inline functions, or implementation work. The command prints the header scan counts. Guest tests establish behavior, error handling, and service availability. The complete conformance gate will combine this inventory with os-test and Open POSIX results.

This tooling does not complete stage 5j / issue #145. The `unistd.h` macros and `sysconf` agree with each other; the complete os-test/Open POSIX gate, the full conformance of the options (stage 5k), and synchronous faults delivered as signals remain separate work after the file-service stage.

## Departures from POSIX.1-2024

- **Utilities (Ф10).** 94 of the 112 utilities of XCU answer `command -v` in the shell image: the ten builtins of `ash`, `sh`, 77 applets of BusyBox 1.37 (a second build of BusyBox, `target/busybox-utils`, only for the image of the shell; the probes keep the small one) and six ready-made programs BusyBox lacks, built from their own sources unchanged (`tools/build-ready-utils.py`) and named as BusyBox applets: `getconf`, `join`, `pathchk` (sbase, MIT), `file`, `iconv` (toybox 0.8.15, 0BSD) and `compress` (ncompress 5.0, public domain; its code tables are 14 bits, 180 kB of static memory, so `compress` writes files of at most 14-bit codes). Not provided, because no ready-made program is built for them yet: `at batch csplit gencat gettext locale localedef lp m4 mailx msgfmt newgrp ngettext pax pr tabs tput write`. `ps` is BusyBox's: `/proc` is made by the layer when a path is opened (`/proc/<pid>/stat`, `statm`, `cmdline`, `status`, `/proc/uptime`, `stat`, `meminfo`, `loadavg`, and `/proc/mounts` in Linux's format for `df`; a path reaches `/proc` by its absolute form, so `./proc/1` from `/` is the same node; the listing of `/proc` names the live PIDs in ascending order, the offset after a PID being the PID plus 4, so a listing in several calls takes each process that lives throughout once; `statvfs` of `/proc` has no blocks) from the List request of the process service; the path is read as text: `/missing/../proc/1` and `/etc/passwd/../proc` succeed (Linux answers ENOENT and ENOTDIR), the search rights of the directories on the way are not checked, and `/link/../proc` is taken by its text; it is read only (EROFS), shows no threads or tty names beyond the terminal's device number, and counts all the time of a process as user time (`utime`); the memory of a process (`VmSize`, `VmRSS`, `statm`, `vsize` and `rss` of `stat`) is the memory charged to its quota, all of it resident; `/proc/meminfo` gives `MemTotal` as the quota of the process service (the memory the POSIX processes share) and `MemFree` and `MemAvailable` as what no process holds of it, with zero for buffers, cache, shared memory and swap; `/proc/stat` has the line `cpu` and `cpu0` (the time all processes ran as user time, those that ended included, which the process service keeps in an account of its own, and the rest of the time since the start as idle time; both only grow), `btime` from the clock, `processes` as the highest PID, and zeros for `intr` and `ctxt`; `/proc/loadavg` gives `0.00 0.00 0.00`, since the layer does not see the scheduler's run queue and keeps no averages, with the number of live processes and the highest PID as the last two fields; `/proc/uptime` has the idle time as the time since the start less the time all processes ran; and the name of a process is the last component of the path of its program (a process of the init table has none, `ps` shows `?`). BusyBox `top` (`top -b -n 1` among them) and `resize` are in the shell image as well. `getlogin` takes the line of the terminal from `/var/run/utmpx` (the image carries one record) and otherwise the owner of the real user ID; `syslog` appends to `/var/log/messages` and writes to the standard error where the file cannot be opened; `utmpx` has no writer in the system (`pututxline` works on a file the process owns, `utmpxname`). `getrusage`, `nice`, `getpriority` and `setpriority` are still not provided.
- **Sockets (Ф9).** AF_UNIX and the IPv4 loopback only; the sockets are descriptions of the pipe service (40 in all, 20 for a session, 28 for a tree of processes, a buffer of 4 KiB each, SO_RCVBUF and SO_SNDBUF report it; the buffer of an AF_UNIX datagram socket holds two datagrams of 800 bytes and reports 1,864 for SO_RCVBUF and 1,600 for SO_SNDBUF). A message carries at most 800 bytes, so a datagram larger than that is EMSGSIZE and a stream send is cut into pieces of 800; an IPv4 datagram to a port nobody has is lost, as on a network, and one that finds the buffer of its receiver full is dropped. `connect` to a listener completes at once (the queue holds 4 connections; a full queue is ECONNREFUSED), so there is no EINPROGRESS. Only 127.0.0.0/8 and 0.0.0.0 are addresses (ENETUNREACH, EADDRNOTAVAIL for others); a name in the file system is a node of kind socket made by `bind`, and `connect` finds the socket by the node number, so a name made anew takes the binding from the stale socket. SCM_RIGHTS carries descriptions of the pipe service (pipe ends and sockets), 8 in a message and 4 messages in flight to a socket; a regular file, a terminal and a FIFO are EOPNOTSUPP. Out-of-band data is the last byte of a stream send with MSG_OOB, apart from the stream. Not provided: SOCK_SEQPACKET, AF_INET6, SCM_CREDENTIALS, SO_LINGER, SO_RCVTIMEO, SO_SNDTIMEO, a blocking `connect` to a full queue. A close of a descriptor by one thread does not wake another thread that waits on it. A socket cannot be sent in a message to itself, while it holds a message with descriptions, or to a socket that is itself in flight (ETOOMANYREFS), so that no cycle keeps a slot.
- **Message queues, semaphores and shared memory (Ф11b).** The POSIX message queues (`mq_*`), the named semaphores (`sem_open`) and the XSI queues, semaphore sets and segments (`msg*`, `sem*`, `shm*`) live in the pipe service (`services/pipe/src/ipc.rs`, protocol `proto/pipe/src/ipc.rs`, three methods). Limits: 16 queues of both kinds, 64 messages of at most 512 bytes in all, up to 64 messages in a queue (`mq_maxmsg`, the size of the pool), 8 semaphore sets of 16 semaphores (named semaphores are sets of one), 8 segments of at most 1 MiB, 8 objects of a kind and 32 of the 64 messages for a tree of processes (a sender that finds the pool used up waits for any message to go); the default `mq_msgsize` is 512, `mq_maxmsg` 8, XSI `msg_qbytes` 8192 (at most 16384). A queue descriptor takes one of the 40 description slots of the sockets, so it counts in the 20 of a session and 28 of a tree; `read`, `write` and `poll` on it fail (poll reports POLLNVAL), and a queue taken out of its name lives until its last descriptor closes. `mq_notify` runs a helper thread of the process that waits in the service; a child of `fork` has no registration. `mq_close` takes off the registration made with that descriptor, also while a child of `fork` holds a copy of it. A `mq_send` that fires the registration of its own process waits (a few milliseconds at most) until the helper has given the notice, so that the signal has arrived when the call returns. A registration with SIGEV_SIGNAL and signal number 0 is taken and sends no signal. `{MQ_PRIO_MAX}` is 32768 (`limits.h`, `sysconf(_SC_MQ_PRIO_MAX)`). The service learns who a caller is from the process service: a session brings a copy of its process's identity session (`posix-id`) with its first request (and again where the service answers that it has none, as in a child of `fork`), the service has it vouched (Vouch, through a notary session as for the clock and the file service; `pipe` is in the VOUCHERS of init) and remembers the answer with the generation of the credentials; only the time comes in the request. The name of a queue or of a named semaphore is taken away by its owner (EACCES otherwise). `SEM_UNDO` keeps 32 adjustments, `shmat` and `sem_open` 48 holds for the service; a process that goes, or replaces its image by `exec`, gives them back in steps, and a child of `fork` gets copies of the holds of its parent (it is counted in `shm_nattch`; `fork` fails with EAGAIN where the holds have no room). The pages of a segment are the file `/dev/shm/.sysvN`, owned by the creator with the mode of the segment (`IPC_SET` follows with `chmod`, `chown` where the caller may), so that the file service refuses those the segment refuses; it is removed with the segment, and where the segment is freed in the service after a process was killed, the next answer to its creator names the file (16 are kept). The name of the file is the creator's 64-bit random number (`getrandom`), made with `O_EXCL` and mode 0600 before it gets the segment's mode, and `shmat` takes the file only if it is a regular file of one link, as long as the segment and owned by the segment's owner or creator (EACCES otherwise), so that a file put in its place in `/dev/shm` is refused. `IPC_SET` changes the file first and the segment after: a new owner or group (which only the superuser may give a file) from anyone else, or a mode its owner may not give, is EPERM and nothing changes. `shmat` takes no address. `semtimedop`, `msgctl` info commands and `IPC_INFO` are not provided. The worst step of the service for these calls is 14,569 ticks of B = 20,410 (with 48 waiting operations) (`cargo xtask posix-ipc-steps`).
- **Message catalogs, crypt, getdate, dlopen (Ф11b).** `catopen`, `catgets` and `catclose` read the catalog format of the BSDs, which `gencat` (FreeBSD's, in the images of os-test only) writes; NLSPATH and the default `/usr/share/nls/%L/%N.cat` are searched. `crypt` knows the traditional DES (musl's code of FreeSec), `setkey` and `encrypt` the same cipher. `getdate` follows DATEMSK. `dlopen(NULL)` answers a handle of the program, `dlsym` finds no symbol by name in a statically linked program, and every other `dlopen` fails with a message that says so.
- **Complex functions (Zh).** The functions of `complex.h` are computed in binary128 and the double and float ones round that value once, so they are correct to the last bit except in about one case in 2^60, with the special values of C11 Annex G (`openlibm/src/stafeto_cplx.h` in the relibc fork). They run at the speed of the software binary128 arithmetic; the floating-point exception flags are those of the intermediate steps.
- **Robust mutexes (Zh).** A thread that ends holding a robust mutex leaves it unlocked and marked: the next `pthread_mutex_lock` returns EOWNERDEAD with the mutex held, `pthread_mutex_consistent` repairs it, and an owner that unlocks it unrepaired makes it ENOTRECOVERABLE. A thread holds at most 64 robust mutexes at a time (EAGAIN beyond). A process that ends while one of its threads holds a robust mutex that lies in shared memory leaves it locked.
- **Typed memory and device control (Zh).** `posix_typed_mem_open`, `posix_typed_mem_get_info`, `posix_mem_offset` and `posix_devctl` are declared and answer that no typed memory object and no device control command exists (ENOENT, ENODEV, EACCES and ENOTTY); `_POSIX_TYPED_MEMORY_OBJECTS` stays unclaimed.
- **File status flags (Zh).** `fcntl(F_GETFL)` on a file of the RAM service returns the access mode and O_APPEND the file was opened with (it gave O_RDWR before); O_NONBLOCK of a file is not recorded. A request for cancellation that came while the state was disabled or before the asynchronous type acts when the thread enables the state or sets the type.
- **Descriptors (Zh).** {OPEN_MAX} is 64: the layer's table, the default of RLIMIT_NOFILE and `sysconf(_SC_OPEN_MAX)` say so, and `dup2`, `dup3` and `F_DUPFD` take numbers up to 63. The services keep their own shares: the file service holds 32 open descriptions for a session and the pipe service 32 ends, so `open` and `pipe` answer EMFILE when the share of their service is full, whatever the table still has free; duplicates of one description cost no share. `poll` and `select` watch 32 descriptors at a time. `SIGSTKSZ` is 48 KiB (was 32 KiB): a handler on the alternate stack may start a program, and the layer's frames for a table of 64 descriptors need more than 32 KiB with the signal frame.
- **Watches (Zh).** `poll`, `ppoll`, `select` and `pselect` watch at most 32 descriptors at a time: more answer EINVAL, where POSIX allows EINVAL only for nfds above {OPEN_MAX} (64 here), so nfds from 33 to 64 with more than 32 open descriptors named differs (stafeto-design#372). Descriptors that are none give EBADF first.
- **Complex at the limits (Zh).** The long double functions of `complex.h` overflow early near LDBL_MAX (their formulas form 1 +- u and call hypotl); the double and float ones, computed in binary128, do not.
- **Numbers (Zh).** `strtod` and `strtof` convert a decimal constant whole with the rounding of the whole constant and set ERANGE on overflow and underflow to zero; `wordexp` prints its words with `printf` (a word `-n` stays); a signal of `aio` with SIGEV_SIGNAL carries `sigev_value` (`sigqueue`). A timed wait (`sem_timedwait`, `pthread_mutex_timedlock`, `pthread_cond_timedwait`) whose absolute deadline lies past a whole second of the clock ends at the deadline (it ended a second late before).
- **Asynchronous I/O and file transfers (Z).** `aio_read`, `aio_write`, `aio_fsync`, `aio_cancel`, `aio_suspend`, `lio_listio`, `aio_error` and `aio_return` run on threads of the library (`src/header/aio` of the fork): the requests of one descriptor are carried out in order by one thread, which ends with the queue, and `{AIO_MAX}` and `{AIO_LISTIO_MAX}` are 128 (`sysconf`; a request past them is EAGAIN). `_POSIX_ASYNCHRONOUS_IO` and `_POSIX_FSYNC` are claimed (202405). A request that has not begun is cancelled (ECANCELED); the one that runs is AIO_NOTCANCELED. A bad descriptor is the error of the request (`aio_error` gives EBADF), except for `aio_fsync`, which fails at once. `aio_error` answers EINVAL for a control block no request was made with and for one whose end `aio_return` took; the second `aio_return` is -1 with EINVAL. A write to a descriptor opened with O_APPEND appends. The notices are SIGEV_SIGNAL with `sigqueue` (the real-time signals of the next paragraph apply) and SIGEV_THREAD in a thread of its own; a list started with LIO_NOWAIT notices once when its last request has ended. A child of `fork` has no requests of its parent. `{_POSIX_PRIORITIZED_IO}` is not claimed and `aio_reqprio` must not be negative. A process has a stack of 64 KiB, so a test that keeps a thousand control blocks on it ends with a fault. `write`, `pwrite`, `read` and `pread` of a regular file take all that is asked, however many messages of the file service it takes (a message holds a little under a kilobyte; a failure after a part gives the count of the part; a pipe, a terminal and a socket return what one call gives). `open` accepts O_SYNC, O_DSYNC and O_RSYNC; the RAM service has every write done when the call returns, and `fcntl(F_GETFL)` does not report them. A write of a regular file longer than one message is not atomic: another process sees a part of it, and with O_APPEND the parts of two writes interleave. `_POSIX_SYNCHRONIZED_IO` is not claimed, and `pathconf(_PC_SYNC_IO)` says -1 to agree. `lio_listio` with more entries than `{AIO_LISTIO_MAX}` is EINVAL. `mq_close` takes off only a registration that its own process made, so a child of `fork` that closes its copy of the descriptor leaves the parent's. The buffer of an AF_UNIX datagram socket is never set below one datagram with the longest sender's address (932 bytes) and its default holds two such datagrams (1,864 bytes; the figures above are those of an unnamed sender).
- **Timers with a function in a thread (Z, stafeto-design#302).** `timer_create` with SIGEV_THREAD makes a timer kept by the library: a helper thread of the timer sleeps until the expiry and runs the function in a detached thread of its own with `sigev_notify_attributes`; no signal number is used. The clocks are CLOCK_REALTIME and CLOCK_MONOTONIC, an absolute CLOCK_REALTIME time is turned into the monotonic scale when the timer is armed, and `timer_getoverrun` counts the periods that passed while the previous notice was due. A child of `fork` does not have the timer.
- **Goal I, threads, signals and scheduling.** A thread stack made by `pthread_create` always has a guard of `guardsize` bytes (one page by default) unless the application gave the stack: the guard is a hole in the layer's room just below the stack (no memory object, no entry in the kernel's table, no frame), so a write below the stack is a translation fault (SIGSEGV), the guard costs no quota whatever its size, and 63 threads each with a guard fit the table of 128 mappings. A `pthread_create` that finds no memory for its stack collects the stacks of threads that ended and tries once more. `pthread_join` and `pthread_detach` of a thread that was joined say ESRCH, of a detached one that ended EINVAL; a thread the layer started itself is taken as live. A wait on a named semaphore that the pipe service has no room to keep (EAGAIN, it keeps a bounded number of waiting operations) is asked again every 2 ms until its deadline: it polls. Signals: `raise` and `pthread_kill` give SI_USER with the PID and UID of the process (XSH 2.4.3); a `sigqueue` queue holds SIGQUEUE_MAX (32) occurrences; all 64 bits of a signal set are signals; an interval below 1 ms of a timer is kept as set and looked at no more often than every millisecond. `setitimer` on ITIMER_VIRTUAL and ITIMER_PROF is the library's, counting the processor time of the process; a zero setting takes the timer off with its interval. A process that sleeps is `S` in `ps` and `top`. `mmap` and `mprotect` refuse PROT_EXEC (EACCES); Open POSIX `mmap/5-1`, `11-2` and `11-3` stay outside PASS for that. Two tests of Open POSIX (`aio_read/9-1`, `aio_write/7-1`) keep 1,024 `struct aiocb` on a stack of 64 KiB: the build makes the array static (`SOURCE_FIXES`). SCHED_OTHER stands at the level `top - 32` of a process only when its ceiling is above 32, else at the ceiling; the image of the test runner has priority 35 and ceiling 36.
- **Goal I, other changes.** A word in a mapping other processes share (`MAP_SHARED`: a semaphore, a mutex, a condition, a barrier or a lock of `pshared` kind in a shared segment) is waited on by looking at it every millisecond, since a wake in the bucket of another process cannot reach the waiting one: such a wait ends within a millisecond of the change, and the waiters do not wake in the order of their priority. `sem_wait` and `sem_timedwait` fail with EINTR when a handler without SA_RESTART ran during the wait. The state of a process in `/proc/<pid>/stat` and `status` is `S` when it has run no ticks since a sample taken at least 2 ms before (any reader of the list takes samples), else `R`. A condition variable made with a monotonic clock in its attributes waits for absolute times of that clock. `pthread_atfork` takes 1,024 handlers of a kind (ENOMEM beyond), `PTHREAD_KEYS_MAX` is 1,024 (EAGAIN beyond), `PTHREAD_STACK_MIN` is 65,536 and `sysconf(_SC_THREAD_STACK_MIN)` says so. `gettimeofday` is `clock_gettime(CLOCK_REALTIME)`. `strftime` knows `%c`, `%G` and `%g`, writes `%U`, `%V` and `%W` with two digits, and `%C` is the century. The headers have `ucontext.h`, `sys/vfs.h` (`statfs` over `statvfs`, the type of the file system 0), `si_band`, `si_fd`, SIGPOLL, `POLL_IN` and its kin, and `POSIX_MADV_DONTNEED`; `_POSIX_SPORADIC_SERVER` and `_POSIX_THREAD_SPORADIC_SERVER` are -1. The runner of Open POSIX gives a test 60 s (120 s for functional and stress tests; timer_settime 5-3 sleeps 150 s by design and has 240 s), starts the tests with `/proc`, `/bin/sleep` and `/bin/ls`, and the processes of the tests have a quota of 1,280 pages. `mmap` and `mprotect` refuse `PROT_EXEC` with EACCES (the objects of the layer carry no right to run code, and a program that generates code must be told); Open POSIX `mmap/5-1`, `mmap/11-2` and `mmap/11-3`, which map executable pages, stay outside PASS for that reason.
- **Real-time signals (I).** The layer has the signals 1 to 64 and the real-time ones from SIGRTMIN (35) to SIGRTMAX (64); `_POSIX_REALTIME_SIGNALS` is claimed (202405) and `sysconf(_SC_SIGQUEUE_MAX)` is 32. The process service keeps the first occurrence of a signal on the page of the process and queues the others behind it in the order they came (a pool of 512 for all processes, 31 behind the page for one): occurrences of `sigqueue` for any signal, and of a real-time signal however it was sent (`kill`, a timer's overrun excepted). A thread that takes an occurrence off the page asks the service for the next (`Page::more`, `account_op::SIGNAL_NEXT`). A `sigqueue` that finds 32 occurrences of `sigqueue` waiting for the process is EAGAIN; `kill` drops the occurrence of a real-time signal that finds the queue full. A process that ignores a signal loses the queue of it at the next signal. `raise` and `pthread_kill` of a real-time signal that waits already for the thread go on as a signal of the process, so another thread may take them. The occurrences wait for the process, not for a thread: a thread's pending signals keep one place for each signal. A timer's signal does not queue (the overrun counts). `sigwaitinfo` and `sigtimedwait` give a signal of a thread (`raise`, `pthread_kill`) with `si_code` SI_USER and the process's PID and real UID. A signal of the set that is not blocked is not refused, and a signal in the set that a handler could take goes to the wait (`sigwait` of an unblocked signal returns it). PID 1 has no record: `kill` and `sigqueue` to it are allowed to a superuser and EPERM for anyone else, and nothing happens.
- **Absolute times (I, stafeto-design#296).** A CLOCK_REALTIME timer set with TIMER_ABSTIME follows a `clock_settime`: the process service moves the deadlines of such timers of all processes by the step of the calendar (`timer_op::CLOCK_STEP`, told by the layer after a successful `clock_settime`; only a superuser may tell it), and a timer that comes due is due at once. A sleep on an absolute time of CLOCK_REALTIME (`clock_nanosleep`) looks at the calendar every 100 ms, so that a set ahead or back moves its end by at most that. The absolute deadlines of `mq_timedsend`, `mq_timedreceive`, `sem_timedwait`, `pthread_mutex_timedlock` and `pthread_cond_timedwait` on CLOCK_REALTIME are still turned into the monotonic scale when the wait begins: a `clock_settime` while they wait does not move the deadline (stafeto-design#339). CLOCK_REALTIME starts at 2026-01-01 00:00:00 UTC (there is no battery clock), generation 0.
- **Processor time (I, stafeto-design#348).** `_POSIX_CPUTIME` and `_POSIX_THREAD_CPUTIME` are claimed. CLOCK_PROCESS_CPUTIME_ID, CLOCK_THREAD_CPUTIME_ID, the clock of a thread (`pthread_getcpuclockid`) and the clock of another process the caller may signal (`clock_getcpuclockid`, read from the process service) are clocks to read. A timer on such a clock (`timer_create`), and ITIMER_VIRTUAL and ITIMER_PROF of `setitimer` are kept by the library, with a helper thread that looks at the clock and sleeps by the fourth of what is left (at least a millisecond): the signal comes within about a millisecond of the time, and the helper thread counts among the threads of the process. A child of `fork` has none. The kernel does not tell the time of a thread in a call from the rest, so all of it is user time and ITIMER_VIRTUAL and ITIMER_PROF count the same time; `clock()` is the processor time of the process. A `pthread_condattr_setclock` with a CPU-time clock is EINVAL. The interval of a periodic timer is kept as set (it was raised to a millisecond): the service looks at a timer with an interval below a millisecond once in a millisecond and counts the expirations in between into the overrun; while the signal of a timer waits, `timer_getoverrun` shows the count of the signal delivered before it, and for a signal that is ignored by default and has no handler (SIGCHLD, SIGCONT, SIGURG, SIGWINCH) the expirations after the first join its overrun.
- **Size of the window.** The terminal answers `TIOCGWINSZ` with the size it holds (0 by 0 until it is told, which BusyBox reads as unknown) and `TIOCSWINSZ` stores a size; a size that differs from the old one sends SIGWINCH to the foreground process group, as on Linux (`stty size`, `stty rows N cols M`, `resize`). The host tells the console its window with a report in the input bytes: GS (0x1D), `W`, the rows, `;`, the columns, GS (`services/tty/src/window.rs`). The serial line of QEMU (the PL011) and the Virtio console of VZ carry no size beside the bytes (QEMU gives no `VIRTIO_CONSOLE_F_SIZE`: its configuration holds zero for columns and rows), so `cargo xtask ash-shell` and `tools/vz-run.swift` send the report at the first prompt and with every SIGWINCH of the host. The console reader takes the report out before the line discipline sees the input; a typed Ctrl-] (the same byte), or the start of a report that does not finish, is held for 75 ms and then reaches the reader as typed, and a report with a zero or a size past 65535 stays input as it came.
