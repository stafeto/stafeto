# Пути ядра без вытеснения

Внутри ядра прерывания замаскированы (спецификация 8.1), поэтому каждый путь
ниже целиком входит во время блокировки любого потока, даже самого
приоритетного. Таблица собирает такие пути с оценкой работы для анализа
времени отклика (спецификация 15.3). Путь, работа которого растёт с размером
объекта, разбивается на порции с точкой продолжения в объекте и опросом
ожидающих прерываний между порциями (`arch::irq_pending`, спецификация 7.7).
С этапа 1.3а последняя ссылка только ставит объект в очередь очистки, и
цикл выхода из ядра (`sched::resume`) делает одну порцию между двумя
опросами прерываний; порция процесса пока разбирает его целиком, стадии с
продвижением в объекте приходят следующим шагом этапа.

| Путь | Что делает | Оценка |
|---|---|---|
| `AddressSpace::destroy` | уводит `TTBR0` с таблиц, `tlbi aside1is`, обходит дерево (512 слов на каждую таблицу уровней 0, 1 и 2) и возвращает каждую таблицу распределителю | число таблиц × 512 чтений |
| `HandleTable::release` | удаляет каждую запись и возвращает каждый кусок, каталог кусков последним; шаг `HandleTable::release_step` берёт один кусок | число кусков × 64, не больше 16 384 записей; шаг: до 64 записей |
| выдача ASID (`tlb::switch_to`, `AsidAllocator::activate`) | ищет свободный номер в карте поколения; выполняется при каждом `thread::run` в процесс, у пространства которого нет ASID текущего поколения: первый запуск пространства и первый запуск после смены поколения | постоянная: до 1024 слов карты при 16-битных ASID, до 4 при 8-битных |
| смена поколения ASID (`tlb::switch_to`) | когда свободных номеров не осталось: обнуляет карту номеров (8 КБ), сбрасывает TLB (`tlbi vmalle1`), затем выдаёт номер, как в строке выше | постоянная: обнуление 8 КБ, сброс TLB и выдача номера |
| `Process::map_frames` | обнуляет блок кадров и отображает каждую его страницу | размер блока; для тестов и загрузки `init` при старте |
| `arch::cache::sync_icache` | `dc cvau` и `ic ivau` по строкам участка; на кэше команд VIPT (A53) вместо `ic ivau` сброс всего кэша команд (`ic ialluis`) | длина участка / размер строки |
| переключение FP/SIMD в `thread::run` | сохраняет регистры уходящего потока и загружает регистры приходящего (по 528 байт) | постоянная: 1056 байт |
| `debug_write` | выводит до 64 байт в PL011 синхронно, ожидая место в очереди передатчика; перед каждым LF ставит CR | до 128 символов: на железе при 115 200 бод и 10 битах на символ около 11 мс, в QEMU мгновенно; право `DEBUG` в 1.2в есть только у `init` |
| последняя ссылка на объект (`object::release`, `process::release`, `thread::release`) | ставит объект в хвост очереди очистки на уровне причины: действующего приоритета потока, чей вызов или сбой отпустил ссылку, или уровня объекта, чья порция её отпустила | постоянная: вставка в хвост уровня и бит маски; вложенного разбора нет |
| порция очистки процесса (`process::clean`) | отпускает объект каждой записи таблицы дескрипторов (каждый встаёт в очередь за O(1)), затем `AddressSpace::destroy`, возврат кадров процесса и место в пуле | число кусков × 64 плюс строка `AddressSpace::destroy`; стадии с продвижением в объекте разобьют её на порции по куску таблицы и по таблице страниц |
| порция очистки потока (`thread::clean`) | снимает страницу буфера сообщений, если она осталась, выводит поток из списка процесса, возвращает место в пуле и отпускает ссылку на процесс | постоянная |
| цикл выхода из ядра (`sched::resume`) | на пустом стеке ядра: опрос `ISR_EL1.I`, подтверждение и обработка прерывания, решение, затем поток, одна порция очистки или `wfi` | постоянная без порции; между двумя опросами прерываний не больше одной порции, и порция начинается только без ожидающего прерывания, поэтому к блокировке любого потока прибавляется самая длинная порция (её меряет ядро для `KSTATS`) |
| решение планировщика (`sched::resume` и события `sched::{start, exit, yield_running, set_priority, timer_fired}`) | операции `kcore::sched`: вставка в голову или хвост уровня, снятие из двусвязного списка, выбор уровня по маске через `clz` с верхним уровнем очереди очистки на входе, срок таймера | постоянная, от числа потоков не зависит; `sched::exit` с последней ссылкой на поток ставит его в очередь очистки |
| запись таймера (`Armed::set`, `sched::timer_fired`) | `CNTV_CVAL_EL0` и `CNTV_CTL_EL0`, затем `isb`, только когда нужный срок изменился; возврат в тот же поток таймер не трогает; прерывание таймера выключает его до EOI | постоянная: на конец кванта три записи системных регистров и два `isb` |
| завершение процесса (`process::end`: `process_kill`, `process_exit`, выход последнего запущенного потока, сбой на EL0) | снимает каждый поток процесса с планировщика, затем отпускает объект каждой записи таблицы дескрипторов, уничтожает адресное пространство, возвращает кадры буферов сообщений и кадры процесса | число потоков процесса плюс строки `HandleTable::release` и `AddressSpace::destroy`; объект, чья последняя ссылка лежала в таблице, встаёт в очередь очистки на уровне вызывающего; в 1.3а разбор таблицы и пространства уходит в очередь очистки; обход потоков процесса (с оболочками вышедших) остаётся в вызове, и в 1.3а нужен предел потоков на процесс |
| сбой на EL0 (`exceptions::user_fault`) | печатает одну строку причины в порт синхронно, затем завершение процесса | до 110 символов: на железе при 115 200 бод около 9,5 мс, в QEMU мгновенно; права не нужны, сбой может вызвать любая программа; в 1.4 печать уходит к драйверу UART; у `init` сверх того регистры программы (до 900 символов), после них машина останавливается; дальше строка «завершение процесса» |
| `process_create` | берёт кадр под корневую таблицу пустого адресного пространства и обнуляет его, берёт место в пуле процессов (новую страницу пула размечает на свободные места), вставляет дескриптор ребёнка в таблицу вызывающего | постоянная: обнуление 512 слов корня, разметка страницы пула, не больше одного нового куска таблицы дескрипторов и её каталога; если дескриптор не поместился, ребёнок встаёт в очередь очистки |
| `thread_create` | берёт кадр для буфера сообщений, обнуляет его и отображает страницу в процесс | постоянная: 512 записей по 8 байт и до трёх новых таблиц |
| `thread_exit` | снимает страницу буфера сообщений со сбросом её записи TLB и возвращает кадр; последний запущенный поток завершает процесс, как в строке «завершение процесса» | постоянная, кроме завершения процесса |
