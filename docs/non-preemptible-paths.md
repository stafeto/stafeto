# Пути ядра без вытеснения

Внутри ядра прерывания замаскированы (спецификация 8.1), поэтому каждый путь
ниже целиком входит во время блокировки любого потока, даже самого
приоритетного. Таблица собирает такие пути с оценкой работы для анализа
времени отклика (спецификация 15.3). Путь, работа которого растёт с размером
объекта, разбивается на порции с точкой продолжения в объекте и опросом
ожидающих прерываний между порциями (`arch::irq_pending`, спецификация 7.7).
Порции и очередь очистки появятся на этапе 1.3; до него такие пути идут
одним вызовом.

| Путь | Что делает | Оценка |
|---|---|---|
| `AddressSpace::destroy` | уводит `TTBR0` с таблиц, `tlbi aside1is`, обходит дерево (512 слов на каждую таблицу уровней 0, 1 и 2) и возвращает каждую таблицу распределителю | число таблиц × 512 чтений |
| `HandleTable::release` | удаляет каждую запись и возвращает каждый кусок | число кусков × 64, не больше 16 384 записей |
| выдача ASID (`tlb::switch_to`, `AsidAllocator::activate`) | ищет свободный номер в карте поколения; выполняется при каждом `thread::run` в процесс, у пространства которого нет ASID текущего поколения: первый запуск пространства и первый запуск после смены поколения | постоянная: до 1024 слов карты при 16-битных ASID, до 4 при 8-битных |
| смена поколения ASID (`tlb::switch_to`) | когда свободных номеров не осталось: обнуляет карту номеров (8 КБ), сбрасывает TLB (`tlbi vmalle1`), затем выдаёт номер, как в строке выше | постоянная: обнуление 8 КБ, сброс TLB и выдача номера |
| `Process::map_frames` | обнуляет блок кадров и отображает каждую его страницу | размер блока; для тестов и загрузки `init` при старте |
| `arch::cache::sync_icache` | `dc cvau` и `ic ivau` по строкам участка; на кэше команд VIPT (A53) вместо `ic ivau` сброс всего кэша команд (`ic ialluis`) | длина участка / размер строки |
| переключение FP/SIMD в `thread::run` | сохраняет регистры уходящего потока и загружает регистры приходящего (по 528 байт) | постоянная: 1056 байт |
| `debug_write` | выводит до 64 байт в PL011 синхронно, ожидая место в очереди передатчика; перед каждым LF ставит CR | до 128 символов: на железе при 115 200 бод и 10 битах на символ около 11 мс, в QEMU мгновенно; право `DEBUG` в 1.2в есть только у `init` |
| последняя ссылка на процесс (`process::release`) | отпускает объект каждой записи таблицы дескрипторов (`HandleTable::release_with`), затем `AddressSpace::destroy` и возврат кадров процесса | число кусков × 64 плюс строка `AddressSpace::destroy`; процесс, чья последняя ссылка лежала в таблице, разбирается тем же путём внутри вызова; в 1.2в вложение не глубже одного уровня, потому что таблица ребёнка пуста; очередь очистки (последняя ссылка кладёт объект в список, разбор идёт порциями с продвижением в объекте) должна появиться в 1.3 раньше передачи дескрипторов |
| решение планировщика (`sched::resume` и события `sched::{start, exit, yield_running, set_priority, timer_fired}`) | операции `kcore::sched`: вставка в голову или хвост уровня, снятие из двусвязного списка, выбор уровня по маске через `clz`, срок таймера | постоянная, от числа потоков не зависит; `sched::exit` с последней ссылкой на поток продолжается `thread::release` и строкой последней ссылки на процесс |
| запись таймера (`Armed::set`, `sched::timer_fired`) | `CNTV_CVAL_EL0` и `CNTV_CTL_EL0`, затем `isb`, только когда нужный срок изменился; возврат в тот же поток таймер не трогает; прерывание таймера выключает его до EOI | постоянная: на конец кванта три записи системных регистров и два `isb` |
